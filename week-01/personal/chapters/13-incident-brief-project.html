مینی‌پروژه: Incident Brief CLI

تمام مفاهیم هفتهٔ اول در یک ابزار کوچک و نزدیک به کار واقعی تو

هدف

یک فایل Log نمونه را بخوانیم، الگوهای واضح Secret را Mask کنیم، از مدل بخواهیم فقط بر اساس شواهد خلاصه تولید کند، Timeout/Retry محدود داشته باشیم و Metadata درخواست را بدون ذخیرهٔ محتوای حساس ثبت کنیم.

sample_incident.log
→
Read & Validate
→
Redact Secrets
→
Build Prompt
→
LLM API
→
Incident Brief + Metrics

خروجی مورد انتظار

  1. Facts: فقط واقعیت‌های موجود در Log.
  2. Likely impact: اثر محتمل با برچسب «استنباط»، نه Fact قطعی.
  3. Unknowns: چیزهایی که شواهد کافی ندارند.
  4. Safe next checks: بررسی‌های Read-only و بدون ساختن Command خیالی.
  5. Confidence: سطح اطمینان و دلیل آن.

اجرای Dry-run بدون API

cd agentic-ai-learning/week-01/personal/examples
python incident_brief_cli.py --file sample_incident.log --dry-run

Dry-run متن Sanitized و Prompt نهایی را نشان می‌دهد اما هیچ Request شبکه‌ای نمی‌فرستد. این بهترین نقطه برای فهمیدن Glue Code و بررسی اینکه چه داده‌ای قرار است از سیستم خارج شود است.

اجرای واقعی

# Linux / Bash
export OPENAI_API_KEY='...'
export OPENAI_MODEL='gpt-5.6'
python incident_brief_cli.py --file sample_incident.log

# Windows PowerShell
$env:OPENAI_API_KEY = '...'
$env:OPENAI_MODEL = 'gpt-5.6'
python .\incident_brief_cli.py --file .\sample_incident.log

مرزهای امنیتی پروژه

  • فقط از Log نمونه استفاده کن؛ Log Production را بدون Data Classification و مجوز به Provider خارجی نفرست.
  • Regex نمونه تمام انواع Secret/PII را پیدا نمی‌کند؛ این یک Demo است، نه DLP سازمانی.
  • Tool اجرایی به پروژه وصل نشده؛ مدل فقط متن تولید می‌کند.
  • Output را شواهد قطعی فرض نکن؛ Unknownها و Citation داخلی Log را بررسی کن.
  • فایل .env و خروجی‌های حساس داخل Git نروند.
