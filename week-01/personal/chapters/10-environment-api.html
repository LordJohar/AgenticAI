Environment Variables و اولین API Call

Config را از Code جدا کن و Request را خط‌به‌خط بفهم

چرا API Key نباید داخل کد باشد؟

Hardcode کردن Secret در Source Code باعث نشت از Git History، Log، Screenshot، Artifact و Code Review می‌شود. Config متغیر مانند Model، Base URL و Timeout نیز بهتر است خارج از کد باشد تا برای Local، CI و Production بدون Patch کردن برنامه تغییر کند.

سه روش تنظیم Environment Variable

Linux / Bash

export OPENAI_API_KEY='...'
export OPENAI_MODEL='gpt-5.6'

Windows PowerShell

$env:OPENAI_API_KEY = '...'
$env:OPENAI_MODEL = 'gpt-5.6'

فایل Local به نام .env

OPENAI_API_KEY=...
OPENAI_MODEL=gpt-5.6

فقط برای Development؛ حتماً داخل .gitignore.

خواندن Config در Python

import os
from dotenv import load_dotenv

load_dotenv()  # در Local فایل .env را می‌خواند؛ در Production لازم نیست

api_key = os.getenv("OPENAI_API_KEY")
model = os.getenv("OPENAI_MODEL", "gpt-5.6")

if not api_key:
    raise RuntimeError("OPENAI_API_KEY is not set")

os.getenv در نبود متغیر مقدار None یا Default می‌دهد. برای Secret بهتر است نبودن مقدار را Fail-fast کنی؛ اما برای Config غیرحساس می‌توان Default منطقی داشت.

اولین Call با SDK

import os
from openai import OpenAI

client = OpenAI(api_key=os.environ["OPENAI_API_KEY"])

response = client.responses.create(
    model=os.getenv("OPENAI_MODEL", "gpt-5.6"),
    instructions=(
        "You are an SRE assistant. Summarize only the supplied evidence. "
        "Do not invent commands, hosts, or causes."
    ),
    input="The pod restarted 4 times after a failed liveness probe.",
)

print(response.output_text)

هر خط چه می‌کند؟

  1. OpenAI(...) یک Client می‌سازد؛ تنظیم Auth، Timeout و Retry در این لایه قرار می‌گیرد.
  2. responses.create(...) یک Request شبکه‌ای می‌فرستد.
  3. model مدل انتخابی را از Config می‌گیرد.
  4. instructions رفتار و محدودیت‌های کلی را مشخص می‌کند.
  5. input داده یا درخواست جاری است.
  6. response.output_text متن خروجی را از ساختار Response جمع می‌کند.
Prompt امنیت ایجاد نمی‌کند. جملهٔ «Secret را چاپ نکن» جای IAM، Network Policy، Secret Store، Redaction و Least Privilege را نمی‌گیرد. Prompt فقط یکی از کنترل‌هاست.

چرخهٔ کامل Request

Read Config
→
Validate Input
→
Build Instructions
→
API Request
→
Validate Response
→
Log Metrics / Return

در Kubernetes

Secret را در Manifest خام Git نگه ندار. بسته به زیرساخت از External Secrets، Vault، Sealed Secrets یا مکانیزم سازمانی استفاده کن. شکل تزریق در Pod می‌تواند چنین باشد:

env:
  - name: OPENAI_API_KEY
    valueFrom:
      secretKeyRef:
        name: llm-provider-credentials
        key: api-key
  - name: OPENAI_MODEL
    value: "gpt-5.6"

Environment Variable برای شروع ساده است، اما Process Inspection، Crash Dump و Debug ممکن است آن را در معرض دید قرار دهد. Permission دسترسی به Pod، Log Policy و Secret Rotation همچنان لازم‌اند.

OpenAI-compatible Endpoint

برخی Gatewayها یا Runtimeهای Self-hosted همان شکل API را ارائه می‌کنند. در این حالت ممکن است base_url نیز Config شود؛ اما سازگاری Endpoint را با سازگاری Capability اشتباه نگیر. 

client = OpenAI(
    api_key=os.environ["LLM_API_KEY"],
    base_url=os.getenv("LLM_BASE_URL"),
)
فایل آماده: نمونهٔ کامل در 02_first_llm_call.py قرار دارد. بدون Key، برنامه با پیام روشن متوقف می‌شود و Secret را چاپ نمی‌کند.
