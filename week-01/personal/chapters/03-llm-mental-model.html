مدل ذهنی درست از LLM

مدل زبان چه کاری انجام می‌دهد و چه کاری انجام نمی‌دهد؟

LLM یا Large Language Model مدلی است که با دیدن حجم بزرگی از داده، الگوهای آماری زبان و انواع ساختارها را یاد گرفته و هنگام اجرا، دنبالهٔ Tokenهای بعدی را تولید می‌کند. همین وظیفهٔ ظاهراً ساده، در مقیاس بزرگ رفتارهایی مثل خلاصه‌سازی، ترجمه، کدنویسی، طبقه‌بندی و پاسخ‌گویی را ممکن می‌کند.

Training در برابر Inference

Training / Post-training

مرحله‌ای پرهزینه که وزن‌های مدل با داده به‌روزرسانی می‌شوند. Pre-training الگوهای عمومی را می‌آموزد؛ Post-training رفتار مدل را برای دنبال کردن دستور، ایمنی و ترجیحات انسانی تنظیم می‌کند.

Inference

همان چیزی که با API مصرف می‌کنی. ورودی Tokenize می‌شود، مدل خروجی را Token به Token می‌سازد و هزینه/Latency ایجاد می‌شود. Request تو معمولاً وزن‌های مدل را تغییر نمی‌دهد.

Training شبیه ساخت و Bake کردن یک Image بزرگ است؛ Inference شبیه اجرای Container از آن Image با Config و Input مشخص. Request عادی تو Image را دوباره Build نمی‌کند، فقط یک اجرای جدید با ورودی جدید است.

Transformer را چقدر باید بفهمی؟

برای هفتهٔ اول همین مدل ذهنی کافی است: Transformer با سازوکار Attention می‌تواند رابطهٔ بخش‌های مختلف ورودی را وزن‌دهی کند؛ یعنی هنگام پردازش یک Token، به Tokenهای مرتبط دیگر توجه متفاوتی دارد. لازم نیست اکنون ماتریس‌های Query/Key/Value را محاسبه کنی، اما باید بدانی Context به مدل اجازه می‌دهد روابط داخل همان ورودی را ببیند.

اصل طلایی: خروجی LLM «بازیابی مستقیم یک رکورد حقیقت» نیست؛ تولید محتمل‌ترین ادامه بر اساس Training، Instruction و Context است. بنابراین روان بودن متن هیچ تضمینی برای درست بودن آن نیست.

مدل به‌تنهایی فقط خروجی تولید می‌کند. Agent زمانی شکل می‌گیرد که برنامه‌ای اطراف مدل تصمیم بگیرد چه زمانی مدل را صدا بزند، چه Toolهایی در اختیارش باشد، نتیجهٔ Tool را چگونه برگرداند، چه زمانی متوقف شود و کجا Human Approval لازم باشد.

Stateless بودن را فراموش نکن

بسیاری از API Callها ذاتاً مستقل‌اند. اگر می‌خواهی مدل «گفت‌وگوی قبلی» را بداند، باید History یا شناسهٔ State را طبق قرارداد API بفرستی. تصور اینکه مدل پشت صحنه همهٔ مکالمه‌ها و فایل‌های تو را همیشه به یاد دارد، یک خطای طراحی است.
