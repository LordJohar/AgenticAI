از شبکهٔ عصبی تا Attention و LLM

هدف این جزوه حفظ‌کردن واژه‌ها نیست. قرار است بفهمیم مدل چگونه عدد می‌بیند، چگونه خطایش را کم می‌کند، چرا Softmax لازم است، Attention چه مسئله‌ای را حل کرد و Transformer چگونه به پایهٔ LLMهای امروزی تبدیل شد.

فارسی مفهومیاصطلاحات تخصصی انگلیسیمثال عددیAttention paper walkthrough

مسیر پیشنهادی: فصل‌ها را به‌ترتیب بخوان. اگر فصل Softmax روشن نباشد، فرمول Attention شبیه یک طلسم ریاضی به نظر می‌رسد.

۰

نقشهٔ راه: دقیقاً چه چیزی می‌سازیم؟

یک زنجیرهٔ علّی، نه فهرستی از اصطلاحات پراکنده.

داده→عدد و بردار→شبکهٔ عصبی→احتمال→توکن و Context→Attention→Transformer / LLM

مدل زبانی در بنیادی‌ترین سطح یک تابع بسیار بزرگ است: عدد می‌گیرد و عدد برمی‌گرداند. متن قبل از ورود به مدل به token id تبدیل می‌شود؛ هر id به embedding vector نگاشت می‌شود؛ لایه‌ها این بردارها را با توجه به context تغییر می‌دهند؛ در پایان برای توکن بعدی مجموعه‌ای logit ساخته و با Softmax به توزیع احتمال تبدیل می‌شود.

معیار یادگیری: در پایان باید بتوانی مسیر text → tokens → embeddings → Transformer blocks → logits → Softmax → next token را بدون نگاه‌کردن توضیح بدهی.

Machine Learning

به‌جای نوشتن همهٔ ruleها، پارامتر‌های یک مدل از exampleها یاد گرفته می‌شوند.

Deep Learning

زیرمجموعه‌ای از ML که از شبکه‌های عصبی چندلایه برای یادگیری representation استفاده می‌کند.

Large Language Model

یک شبکهٔ عصبی زبانی با پارامترهای فراوان و دادهٔ زیاد؛ معمولاً مبتنی بر Transformer و هدف پیش‌بینی توکن.

آیا برای فهم این جزوه باید Calculus بلد باشم؟

نه. مشتق و گرادیان را ابتدا به‌صورت «جهت و شدت تغییر» می‌فهمیم. فرمول‌ها برای اتصال intuition به کد هستند، نه آزمون ریاضی.

۱

عدد، بردار، ماتریس و تنسور

زبان مشترک تمام محاسبات مدل.

Scalar یک عدد است؛ مثلاً دما یا یک امتیاز. بردار لیستی مرتب از اعداد است؛ مثلاً نمایش یک توکن با ۷۶۸ ویژگی آموخته‌شده. ماتریس جدولی دوبعدی از اعداد است. تنسور نام عمومی آرایه‌ای با هر تعداد بعد است.

ابعاد تنسور (shape)

scalar:  3.2               shape: []
vector:  [0.2, -1.1, 0.7] shape: [3]
matrix:  4 tokens × 8 dims shape: [4, 8]
batch:   32 × 4 × 8       shape: [32, 4, 8]

وزن و بایاس

weight مشخص می‌کند هر ورودی چه اندازه و با چه علامتی اثر بگذارد. bias یک offset قابل‌یادگیری است تا مدل مجبور نباشد همه‌چیز را از صفر عبور دهد.

y = Wx + b

ضرب داخلی: یک عدد برای میزان هم‌جهتی

دو بردار هم‌اندازه را عضو‌به‌عضو ضرب و جمع می‌کنیم. در Attention از این عملیات برای ساخت امتیاز شباهت Query و Key استفاده می‌شود.

[1, 2, 0] · [3, -1, 4] = (1×3) + (2×-1) + (0×4) = 1

ضرب داخلی بزرگ‌تر می‌تواند نشانهٔ هم‌جهتی بیشتر باشد، اما طول بردار هم روی آن اثر دارد. cosine similarity جهت را با نرمال‌کردن طول مقایسه می‌کند.

بُعد یعنی چه؟

وقتی می‌گوییم embedding دارای ۷۶۸ بُعد است، منظور ۷۶۸ محور آموخته‌شده است. معمولاً نمی‌توان گفت محور ۴۲ دقیقاً «رسمی‌بودن» است؛ معنا میان تعداد زیادی بُعد توزیع شده است.

چرا مدل فقط با عدد کار می‌کند؟

پردازنده عملیات جمع و ضرب را روی آرایه‌های عددی بسیار سریع اجرا می‌کند. آموزش هم به تابع‌های پیوسته و قابل‌مشتق نیاز دارد؛ string خام چنین ساختاری ندارد.

۲

از مدل خطی تا نورون

کوچک‌ترین واحد محاسباتی را بدون استعارهٔ زیستی بفهمیم.

یک نورون مصنوعی چند ورودی را با وزن‌هایشان ترکیب می‌کند، بایاس را اضافه می‌کند و معمولاً نتیجه را از یک activation function عبور می‌دهد:

z = w₁x₁ + w₂x₂ + … + wₙxₙ + b     ;     a = activation(z)

مثلاً برای تخمین احتمال incident، x₁ می‌تواند تعداد errorها و x₂ تأخیر باشد. مدل هنگام training یاد می‌گیرد کدام ویژگی مهم‌تر است. نورون یک مغز کوچک یا محل ذخیرهٔ یک مفهوم کامل نیست؛ فقط یک محاسبهٔ پارامتری است.

پارامتر: مقداری که مدل از داده یاد می‌گیرد؛ مانند وزن و بایاس. Hyperparameter: انتخابی بیرونی مانند نرخ یادگیری، batch size یا تعداد لایه‌ها.

Forward Pass

حرکت از input به پیش‌بینی را forward pass می‌نامیم. هنوز چیزی یاد گرفته نشده؛ فقط با پارامتر‌های فعلی خروجی محاسبه شده است.

آیا هر نورون یک کلمه یا مفهوم مشخص را تشخیص می‌دهد؟

گاهی واحدهایی به pattern خاص حساس می‌شوند، اما representation معمولاً distributed است. نسبت‌دادن یک مفهوم انسانی ثابت به هر نورون مدل ذهنی قابل‌اعتمادی نیست.

۳

شبکهٔ عصبی و لایه‌ها

چرا یک خط کافی نیست و «عمیق» چه معنایی دارد؟

لایهٔ ورودی
x→Linear + Activation→Hidden representation→Output logits

ترکیب چند تابع خطی بدون activation هنوز یک تابع خطی است. غیرخطی‌بودن اجازه می‌دهد شبکه رابطه‌های پیچیده را مدل کند. Deep یعنی چندین مرحلهٔ representation پشت سر هم قرار گرفته‌اند.

لایه

یک تبدیل مشخص روی تنسور. در Transformer، Attention و Feed-Forward هر دو نوعی لایه / زیرلایه هستند.

Representation

شکل عددی‌ای که مدل در یک مرحله برای بیان اطلاعات ساخته است.

تعداد پارامترها

تعداد وزن‌ها و بایاس‌های قابل‌یادگیری. «۷B» تقریباً یعنی هفت میلیارد پارامتر، نه هفت میلیارد خط کد.

معماری

نقشهٔ اتصال لایه‌ها و جریان داده. Training پارامترها را تعیین می‌کند؛ معماری ظرف محاسبات است.

تعمیم و Overfitting

هدف حفظ‌کردن training set نیست؛ مدل باید روی example ندیده خوب کار کند. اگر training loss پایین ولی زیان اعتبارسنجی بالا باشد، احتمال overfitting وجود دارد. تقسیم train/validation/test کمک می‌کند یادگیری را از حفظ‌کردن جدا کنیم.

۴

Training: زیان، گرادیان و Backpropagation

مدل دقیقاً چگونه وزن‌هایش را تغییر می‌دهد؟

  1. Forward pass: مدل با وزن‌های فعلی پیش‌بینی می‌سازد.
  2. زیان: یک عدد نشان می‌دهد پیش‌بینی چقدر با مقدار هدف فاصله دارد.
  3. Backward pass: backpropagation سهم هر پارامتر در زیان را با chain rule محاسبه می‌کند.
  4. گام بهینه‌ساز: پارامتر‌ها کمی در جهت کاهش زیان تغییر می‌کنند.
  5. این چرخه روی batchهای فراوان تکرار می‌شود.
w_new = w_old − learning_rate × ∂Loss/∂w

gradient برداری از مشتق‌هاست: اگر هر پارامتر کمی تغییر کند، زیان با چه جهت و شدتی تغییر می‌کند؟ gradient descent در خلاف جهت گرادیان حرکت می‌کند. learning rate اندازهٔ گام است؛ خیلی بزرگ می‌تواند training را ناپایدار و خیلی کوچک آن را کند کند.

Epoch

یک بار عبور تقریبی از کل training set.

Batch

گروهی از exampleها که یک‌جا پردازش و گرادیان آن‌ها تجمیع می‌شود.

بهینه‌ساز

قاعدهٔ به‌روزرسانی پارامتر‌ها؛ مانند SGD یا Adam.

Vanishing و گرادیان انفجاری

در زنجیره‌های بسیار عمیق یا recurrent، ضرب مشتق‌ها ممکن است گرادیان را نزدیک صفر یا بسیار بزرگ کند. ReLU، نرمال‌سازی، residual connection، initialization مناسب و محدودسازی گرادیان از ابزارهای کنترل‌اند.

Backpropagation با گرادیان کاهشی یکی است؟

نه. Backpropagation گرادیان‌ها را به‌شکل کارآمد محاسبه می‌کند؛ گرادیان کاهشی یا بهینه‌ساز از آن‌ها برای update کردن پارامتر‌ها استفاده می‌کند.

منبع غیرخطی‌بودن و رفتارهای متفاوت خروجی.

تابعفرمول/بازهشهود و کاربرد

۶

Logit، Softmax و Cross-Entropy

پل میان امتیاز خام، احتمال و انتخاب توکن.

Logit چیست؟

خروجی خام مدل برای هر class یا توکن را logit می‌نامیم. logit احتمال نیست: می‌تواند منفی یا بزرگ‌تر از ۱ باشد و مجموعش محدودیتی ندارد.

softmax(zᵢ) = exp(zᵢ) / Σⱼ exp(zⱼ)

Softmax سه کار می‌کند: با exponential همهٔ مقدارها را مثبت می‌کند؛ امتیاز بزرگ‌تر را برجسته می‌کند؛ سپس با تقسیم بر مجموع، خروجی‌ها را به احتمال‌هایی تبدیل می‌کند که جمعشان ۱ است.

مثال دستی

برای logits برابر [2, 1, 0]، مقدارهای نمایی تقریباً [7.39, 2.72, 1] و مجموع 11.11 است؛ پس احتمال‌ها حدود [0.665, 0.245, 0.090] می‌شوند.

Numerical stability: در کد واقعی ابتدا بزرگ‌ترین logit را از همه کم می‌کنیم. Softmax تغییر نمی‌کند، ولی از overflow در exp جلوگیری می‌شود.

آزمایش تعاملی Softmax و Temperature

Temperature قبل از Softmax logits را تقسیم می‌کند. T < 1 توزیع را متمرکزتر و T > 1 آن را تخت‌تر می‌کند. Temperature دانش مدل را عوض نمی‌کند، فقط نمونه‌گیری از امتیاز‌های فعلی را تغییر می‌دهد.

Cross-Entropy چه می‌سنجد؟

اگر مقدار هدف صحیح class شمارهٔ ۲ باشد، زیان ساده برابر -log(p₂) است. احتمال زیاد برای جواب درست زیان کوچک و احتمال کم زیان بزرگ می‌دهد.

CrossEntropy(target=k) = −log(softmax(logits)ₖ)
آیا خروجی Softmax «اعتماد واقعی» مدل است؟

نه لزوماً. احتمال مدل ممکن است calibration خوبی نداشته باشد. ۹۰٪ در توزیع خروجی تضمین نمی‌کند پاسخ در جهان واقعی ۹۰٪ درست است.

۷

توکن، Vocabulary، One-Hot و Embedding

چگونه متن به ورودی عددی معنادار تبدیل می‌شود؟

Tokenizer متن را به واحدهایی به نام توکن تقسیم می‌کند. توکن ممکن است یک کلمه، بخشی از کلمه، علامت یا byte باشد. سپس هر توکن از vocabulary یک id می‌گیرد. id فقط شناسه است و نزدیکی عددی idها معنایی ندارد.

text:      "مدل‌ها یاد می‌گیرند"
tokens:    ["مدل", "‌ها", " یاد", " می", "‌گیرند"]
token_ids: [8142, 391, 2207, 118, 9201]   # illustrative only

One-Hot چرا کافی نیست؟

در بردار one-hot فقط خانهٔ مربوط به id برابر ۱ است. دو کلمهٔ مشابه و نامشابه فاصله‌ای یکسان دارند و بردار بسیار بزرگ و sparse است. embedding table برای هر توکن یک بردار dense و قابل‌یادگیری نگه می‌دارد.

embedding(token_id) = row[token_id] from E ∈ ℝ^(vocab_size × d_model)

Word2Vec چه ایده‌ای اضافه کرد؟

Word2Vec embedding را از یک task جانبی یاد می‌گیرد: در Skip-gram از کلمهٔ مرکزی همسایه‌ها پیش‌بینی می‌شوند و در CBOW از همسایه‌ها کلمهٔ مرکزی. واژه‌هایی با context مشابه بردارهای نزدیک‌تری پیدا می‌کنند. محدودیت: یک واژه معمولاً یک بردار static دارد و چندمعنایی را با context حل نمی‌کند.

Subword Tokenization

تقسیم به subword میان vocabulary کاملاً کلمه‌ای و character-level تعادل ایجاد می‌کند: واژهٔ نادر می‌تواند از بخش‌های آشناتر ساخته شود. BPE یکی از روش‌های تاریخی مهم این مسیر است. مرز توکن همیشه با مرز واژه یا معنا یکی نیست.

توکن ≠ word: هزینه، context length و احتمال خروجی بر حسب توکن محاسبه می‌شوند. یک واژهٔ فارسی ممکن است چند توکن شود.
۸

Sequence، RNN و گلوگاه Context

چرا قبل از Transformer پردازش ترتیبی مسئله‌ساز بود؟

معنای زبان به ترتیب و context وابسته است. RNN در هر time step ورودی فعلی و hidden state قبلی را ترکیب می‌کند:

hₜ = f(xₜ, hₜ₋₁)

این state خلاصه‌ای از گذشته است. LSTM و GRU با gateها جریان حافظه و گرادیان را بهتر کردند، اما سه محدودیت اصلی باقی ماند:

Sequential compute

برای محاسبهٔ h₁₀ ابتدا h₉ لازم است؛ موازی‌سازی دشوار می‌شود.

Long dependency

رابطهٔ دو توکن دور باید از stateهای میانی زیادی عبور کند.

Fixed bottleneck

Encoder کلاسیک کل ورودی را به یک بردار ثابت برای Decoder تحویل می‌داد.

Attention ابتدا برای رفع گلوگاه آخر در Neural Machine Translation مطرح شد: Decoder به‌جای تکیه بر یک خلاصهٔ ثابت، در هر گام به همهٔ stateهای Encoder نگاه می‌کند.

۹

Attention: جست‌وجوی نرم در حافظه

Q، K، V و Softmax را از یک مثال ملموس بسازیم.

Query بیان می‌کند «چه می‌خواهم؟»، هر Key می‌گوید «این رکورد با چه ویژگی‌ای قابل‌جست‌وجوست؟» و Value محتوایی است که در صورت مرتبط‌بودن برداشته می‌شود. برخلاف database lookup سخت، Attention معمولاً همهٔ Valueها را با وزن متفاوت ترکیب می‌کند.

Query (Q)

نیاز representation فعلی؛ دنبال چه رابطه‌ای هستم؟

Key (K)

نمایهٔ قابل‌مقایسهٔ هر موقعیت برای محاسبهٔ relevance.

Value (V)

اطلاعاتی که پس از تعیین وزن واقعاً تجمیع می‌شود.

  1. از representation ورودی با ماتریس‌های آموختنی، Q و K و V بساز.
  2. برای هر Query، با ضرب داخلی همهٔ Keyها امتیاز بساز.
  3. امتیاز را بر √dₖ تقسیم کن تا دامنه کنترل شود.
  4. با Softmax، امتیازها را به attention weight تبدیل کن.
  5. جمع وزن‌دار Valueها را خروجی بگیر.
Attention(Q,K,V) = softmax(QKᵀ / √dₖ) V

اگر امتیاز‌های یک Query برای سه توکن برابر [2, 1, 0] باشند، Softmax تقریباً وزن‌های [0.665, 0.245, 0.090] می‌سازد. خروجی 0.665V₁ + 0.245V₂ + 0.090V₃ است؛ مدل فقط یک توکن را انتخاب نکرده است.

چرا مقیاس‌بندی؟

با بزرگ‌شدن بُعد، ضرب‌های داخلی می‌توانند magnitude بزرگی پیدا کنند. Softmax روی اختلاف‌های بزرگ اشباع و گرادیان کوچک می‌شود. تقسیم بر ریشهٔ بُعد کلید، واریانس امتیازها را کنترل می‌کند.

Q/K/V خود توکن نیستند: projectionهای متفاوتی از representation هستند: Q=XWQ, K=XWK, V=XWV.

ترجمهٔ مفهومی «Attention Is All You Need»

مقالهٔ Vaswani و همکاران، ۲۰۱۷؛ شرح محتوایی به‌جای ترجمهٔ کلمه‌به‌کلمه.

ایدهٔ مرکزی مقاله: برای sequence transduction لازم نیست recurrence یا convolution هستهٔ ارتباط میان توکن‌ها باشد. می‌توان معماری Encoder–Decoder را بر Attention بنا کرد، موقعیت‌های هر لایه را موازی‌تر محاسبه کرد و مسیر ارتباط توکن‌های دور را کوتاه کرد.

مسئله‌ای که مقاله از آن شروع می‌کند

مدل‌های ترجمهٔ قوی آن زمان عمدتاً RNN/CNN بودند. RNN محاسبه را ترتیبی می‌کرد و dependency دور مسیر بلندی داشت. Attention پیش‌تر در کنار RNN موفق شده بود، اما این مقاله پرسید: اگر Attention را از جزء کمکی به سازوکار اصلی تبدیل کنیم چه می‌شود؟ پاسخ معماری Transformer بود.

Abstract به زبان ساده

نویسندگان یک Encoder–Decoder بدون recurrence و convolution پیشنهاد کردند که برای ارتباط میان موقعیت‌ها از Attention استفاده می‌کند. در آزمایش‌های ترجمهٔ انگلیسی–آلمانی و انگلیسی–فرانسوی، مدل آن‌ها کیفیت قوی و training موازی‌پذیرتری ارائه کرد. مقاله همچنین تعمیم معماری را روی parsing بررسی کرد.

شکل کلی معماری مقاله

توکن‌های مبدأ

توزیع خروجی

Encoder چه می‌کند؟

هر لایهٔ Encoder در مقاله دو زیرلایه دارد: Multi-Head Self-Attention و یک position-wise Feed-Forward Network. دور هر زیرلایه یک residual connection و سپس نرمال‌سازی لایه قرار می‌گیرد. هر توکن از توکن‌های دیگر همان ورودی information می‌گیرد.

Decoder چه می‌کند؟

Decoder سه زیرلایه دارد: masked Self-Attention روی توکن‌های خروجی قبلی، Cross-Attention که Query را از Decoder و Key/Value را از Encoder می‌گیرد، و Feed-Forward. Mask اجازه نمی‌دهد موقعیت خروجی پاسخ آینده را ببیند.

Scaled Dot-Product Attention

مقاله Queryها را با Keyها ضرب می‌کند، scale را اعمال می‌کند، mask احتمالی را پیش از Softmax وارد می‌کند و وزن‌های حاصل را روی Valueها می‌زند. ماتریس ارتباط همهٔ Queryها با همهٔ Keyها هم‌زمان ساخته می‌شود.

Multi-Head یعنی چه؟

به‌جای یک Attention، Q/K/V به چند فضای کوچک‌تر project می‌شوند. هر head Attention مستقل خود را محاسبه می‌کند؛ خروجی headها concatenate و با projection نهایی مخلوط می‌شود. مدل می‌تواند چند نوع رابطه را در subspaceهای مختلف دنبال کند، اما هر head الزاماً یک مفهوم انسانی ثابت ندارد.

headᵢ = Attention(QWᵢQ, KWᵢK, VWᵢV)
MultiHead = Concat(head₁,…,headₕ)Wᴼ

موقعیت چرا لازم است؟

Self-Attention خام ترتیب را از index نمی‌فهمد. مقاله sinusoidal positional encoding را به embedding ورودی اضافه کرد. Transformerهای بعدی روش‌های دیگری مانند موقعیت آموخته‌شده یا موقعیت چرخشی به‌کار بردند؛ اصل نیاز به موقعیت پابرجاست.

Feed-Forward، Residual و نرمال‌سازی

Attention میان توکن‌ها اطلاعات جابه‌جا می‌کند. FFN روی هر موقعیت یک تبدیل nonlinear انجام می‌دهد. Residual مسیر مستقیم عبور اطلاعات می‌سازد و نرمال‌سازی، آموزش را پایدارتر می‌کند. پس عنوان مقاله به معنی حذف همهٔ اجزای غیر Attention نیست.

Embedding تا Vocabulary

در انتهای Decoder، linear projection برای هر توکن واژگان logit می‌سازد و توزیع Softmax خروجی را تولید می‌کند. هنگام training، sequence هدف یک موقعیت shift می‌شود: prefix ورودی است و توکن بعدی برچسب.

چرا path length مهم بود؟

در RNN انتقال اطلاعات از ابتدای sequence به انتها چندین step داشت. در Self-Attention، هر موقعیت در یک لایه مستقیماً با هر موقعیت مجاز امتیاز دارد. هزینهٔ مهم آن، ماتریس توجه با رشد تقریباً quadratic نسبت به sequence length است.

مقاله چه چیزی نمی‌گوید؟

  • مقاله دربارهٔ chatbot، instruction following، RLHF، agent یا استفاده از ابزار نیست.
  • ثابت نمی‌کند recurrence برای همهٔ مسئله‌ها بی‌ارزش شده است.
  • نمی‌گوید Attention توضیح‌پذیری کامل فراهم می‌کند.
  • Transformerهای امروز جزئیات اجرایی متفاوتی با نسخهٔ original دارند.
خلاصهٔ یک‌دقیقه‌ای: مقاله گلوگاه پردازش ترتیبی را هدف گرفت؛ با Self-Attention ارتباط مستقیم میان توکن‌ها ساخت؛ Multi-Head چند projection موازی داد؛ موقعیت ترتیب را وارد کرد؛ Encoder/Decoder با FFN، residual و نرمال‌سازی کامل شدند؛ Linear + Softmax، توکن خروجی را پیش‌بینی کرد.
چرا عنوان «Attention Is All You Need» کمی اغراق‌آمیز است؟

چون مدل علاوه بر Attention به embedding، positional encoding، FFN، residual، نرمال‌سازی، objective، بهینه‌ساز و داده نیاز دارد. عنوان به حذف recurrence/convolution از هستهٔ sequence modeling اشاره می‌کند.

Causal Mask

در موقعیت شمارهٔ t، امتیاز‌های آینده با مقدار بسیار منفی mask می‌شوند تا پس از وزن Softmax تقریباً صفر بگیرند. بدون mask، مدل هنگام training پاسخ آینده را می‌بیند.

Multi-Head و ابعاد

اگر d_model=512 و h=8 باشد، معمولاً هر head بعد ۶۴ دارد. Q/K/V برای همهٔ توکن‌ها ساخته و به headها reshape می‌شوند. خروجی headها دوباره به بُعد اصلی برمی‌گردد.

Residual Stream

می‌توان representation هر توکن را یک stream در نظر گرفت. Attention و MLP تغییراتی به آن اضافه می‌کنند. Residual باعث می‌شود هر زیرلایه لازم نباشد representation را از صفر بازسازی کند.

از Transformer تا LLM

Pre-training، objective و رفتاری که از scale پدیدار می‌شود.

Pre-training

در decoder-only language model، متن به exampleهای فراوان پیش‌بینی توکن بعدی تبدیل می‌شود. برچسب از خود متن می‌آید، بنابراین روش self-supervised است. مدل برای کاهش Cross-Entropy مجبور می‌شود الگوهای syntax، semantics، سبک و facts موجود در داده را در پارامتر‌هایش فشرده کند.

P(x₁,…,xₙ) = ∏ₜ P(xₜ | x₁,…,xₜ₋₁)

BERT چه تفاوتی دارد؟

BERT اصلی Encoder-only و bidirectional است. بخشی از توکن‌ها در Masked Language Modeling پنهان/خراب می‌شوند و مدل با context چپ و راست آن‌ها را بازسازی می‌کند. interface پیش‌فرضش تولید autoregressive آزاد نیست.

یادگیری عمومی از corpus بزرگ؛ بسیار پرهزینه و طولانی.

Fine-tuning / Alignment

تطبیق behavior یا task با dataset کوچک‌تر.

Inference

استفاده از پارامتر‌های ثابت برای پردازش prompt و تولید output.

Context Window و حافظهٔ پارامترها

Context window فضای موقت توکن‌های همین request است. پارامتر‌ها الگوهای فشردهٔ training هستند. افزودن سند به prompt با تغییر وزن‌ها یکی نیست؛ Retrieval اطلاعات را موقتاً در context می‌آورد، Fine-tuning behavior را در پارامتر‌ها تغییر می‌دهد.

Inference و Decoding

چگونه توزیع به متن خروجی تبدیل می‌شود؟

  2. از logits آخرین موقعیت یک توکن انتخاب می‌شود.
  3. توکن انتخابی به context افزوده و گام بعد اجرا می‌شود (decode).
  4. این حلقه تا توکن توقف یا محدودیت خروجی ادامه می‌یابد.

KV Cache

در generation لازم نیست Key و توکن‌های Value قبلی در هر step دوباره محاسبه شوند؛ KV cache آن‌ها را نگه می‌دارد. تأخیر کم می‌شود ولی memory با طول context رشد می‌کند.

قطعی ≠ correct: temperature پایین ممکن است خروجی را تکرارپذیرتر کند، اما اگر محتمل‌ترین ادامه غلط باشد همان غلط را انتخاب می‌کند.

Hallucination، محدودیت و روش تطبیق

چرا پیش‌بینی توکن بعدی پایگاه حقیقت نیست؟

Hallucination یعنی خروجی روان و ظاهراً معتبر که با شواهد یا واقعیت پشتیبانی نمی‌شود. مدل برای تولید continuation محتمل آموزش دیده، نه برای query خودکار روی حقیقت بیرونی. عبارت hallucinated در این حوزه یعنی تولید بدون پشتوانه، نه تجربهٔ انسانی یا پزشکی.

Retrieval / RAG

سند مرتبط را هنگام request وارد context کن؛ مناسب دانش تازه، خصوصی و قابل‌استناد.

استفاده از ابزار

برای log، database، calculator یا API به‌جای حدس، observation واقعی بگیر.

خروجی ساختاریافته

schema شکل خروجی را کنترل می‌کند؛ صحت factual را به‌تنهایی تضمین نمی‌کند.

ارزیابی

روی dataset دیده‌نشده، metric و baseline تعریف کن.

Fine-tuning، LoRA و QLoRA

در full fine-tuning همهٔ پارامتر‌ها update می‌شوند. LoRA وزن پایه را freeze می‌کند و update را با دو ماتریس کم‌رتبه یاد می‌گیرد: ΔW=BA. QLoRA مدل پایهٔ freezeشده را quantized نگه می‌دارد و گرادیان را به LoRA adapterها عبور می‌دهد تا memory کمتر شود. این روش‌ها برای behavior و domain مناسب‌اند، نه جایگزین database تازه.

W′ = W + BA    where rank r ≪ model dimension

Quantization

نمایش وزن‌ها با bit کمتر memory و bandwidth را کاهش می‌دهد، اما ممکن است approximation error وارد کند. storage dtype، compute dtype و dtype پارامترهای trainable جدا هستند؛ «مدل ۴ بیتی» به معنی ۴ بیتی‌بودن همهٔ عملیات نیست.

قاعدهٔ تصمیم: دانش متغیر → Retrieval؛ اقدام/مشاهدهٔ بیرونی → Tool؛ قالب معتبر → Schema؛ رفتار تکراری با example کافی → Fine-tuning؛ و در همهٔ حالت‌ها → ارزیابی.

خودآزمایی نهایی

۱. فرق logit و احتمال چیست؟

امتیاز Logit خام و نامحدود است. Softmax مجموعهٔ logitها را به احتمال‌های مثبت با مجموع ۱ تبدیل می‌کند.

۲. چرا Softmax داخل Attention استفاده می‌شود؟

امتیاز سازگاری Query/Key را به وزن‌های نسبی تبدیل می‌کند تا Valueها با یک توزیع وزن‌دار جمع شوند.

۳. Transformer بدون Attention چه اجزای مهم دیگری دارد؟

Embedding، positional information، FFN/MLP، residual، نرمال‌سازی، output projection و training objective.

۴. چرا RAG با Fine-tuning یکی نیست؟

شواهد RAG را هنگام request در context می‌آورد؛ پارامترهای Fine-tuning را برای behavior/task تغییر می‌دهد.

۵. آیا Attention weight توضیح قطعی reasoning مدل است؟

نه. می‌تواند سرنخ ارتباط باشد، اما به‌تنهایی تبیین علّی و کامل رفتار مدل نیست.
