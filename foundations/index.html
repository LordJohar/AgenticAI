حالت مطالعه از صفر

قبل از تیک‌زدن، فقط یک کار مهم داری: بتوانی با زبان خودت توضیح بدهی.

این جزوه قرار نیست با تعریف‌های خشک شروع شود. از این به بعد هر فصل را مثل یک روند سادهٔ یادگیری بخوان: اطلاعات وارد می‌شود، به عدد تبدیل می‌شود، یک پیش‌بینی ساخته می‌شود، فاصلهٔ پیش‌بینی تا جواب درست اندازه‌گیری می‌شود و مدل کم‌کم اصلاح می‌شود. اگر یک پاراگراف هنوز مبهم بود، تیک نزن؛ یعنی هنوز نتوانسته‌ای آن را با زبان خودت بازگو کنی.

مدلمثل یک جعبهٔ تصمیم‌گیر است: ورودی می‌گیرد، آن را به عدد تبدیل می‌کند و بر اساس چیزهایی که یاد گرفته خروجی می‌سازد.
پارامترچیزی است که مدل خودش از مثال‌ها یاد می‌گیرد؛ مثل اینکه بفهمد کدام نشانه در جواب نهایی مهم‌تر است.
گرادیانراهنمای اصلاح است: می‌گوید برای کمترشدن اشتباه، هر مقدار آموختنی باید به کدام سمت و چقدر تغییر کند.
Retrievalیعنی قبل از جواب‌دادن، اطلاعات مرتبط را پیدا کنیم و جلوی مدل بگذاریم؛ مثل پاسخ‌دادن با کتاب باز، نه فقط با حافظه.
قانون تیک: فقط وقتی تیک بزن که بتوانی جواب بدهی: «این فصل چه مشکلی را حل می‌کند؟ ورودی و خروجی‌اش چیست؟ اگر بخواهم برای یک نفر دیگر توضیحش بدهم، از چه مثال ساده‌ای شروع می‌کنم؟»
۰

نقشهٔ راه: دقیقاً چه چیزی می‌سازیم؟

یک زنجیرهٔ علّی، نه فهرستی از اصطلاحات پراکنده.

داده→عدد و بردار→شبکهٔ عصبی→احتمال→توکن و Context→Attention→Transformer / LLM

مدل زبانی در بنیادی‌ترین سطح یک تابع بسیار بزرگ است: عدد می‌گیرد و عدد برمی‌گرداند. متن قبل از ورود به مدل به token id تبدیل می‌شود؛ هر id به embedding vector نگاشت می‌شود؛ لایه‌ها این بردارها را با توجه به context تغییر می‌دهند؛ در پایان برای توکن بعدی مجموعه‌ای logit ساخته و با Softmax به توزیع احتمال تبدیل می‌شود.

معیار یادگیری: در پایان باید بتوانی مسیر text → tokens → embeddings → Transformer blocks → logits → Softmax → next token را بدون نگاه‌کردن توضیح بدهی.

چطور این نقشه را بفهمم؟

به کل مسیر مثل تبدیل چندمرحله‌ای نگاه کن. متن خام برای مدل قابل‌فهم نیست؛ اول باید به واحدهای کوچک‌تر تبدیل شود، بعد هر واحد به بردار عددی برود، بعد لایه‌ها این بردارها را با توجه به بقیهٔ متن اصلاح کنند، و آخر کار مدل برای توکن بعدی چند امتیاز خام بسازد.

  • مثال جمله: در جملهٔ «امروز هوا خیلی ...»، مدل برای ادامه‌هایی مثل «خوب»، «سرد» یا «گرم» امتیاز می‌سازد. هنوز جواب قطعی نداریم؛ فقط گزینه‌هایی با احتمال متفاوت داریم.
  • مثال ترجمه: برای ترجمهٔ یک جمله، مدل باید بفهمد کدام کلمهٔ مقصد به کدام بخش جملهٔ مبدأ مربوط است. اینجا Attention کمک می‌کند بخش‌های مرتبط وزن بیشتری بگیرند.
  • مثال خلاصه‌سازی: وقتی یک متن بلند خلاصه می‌شود، مدل باید از میان اطلاعات زیاد تشخیص دهد کدام بخش‌ها برای ادامهٔ خروجی مهم‌ترند.

اشتباه رایج این است که فکر کنیم مدل «متن را مثل انسان می‌خواند». دقیق‌تر این است: متن به عدد تبدیل می‌شود، و مدل روی عددها عملیات یادگرفته‌شده انجام می‌دهد.

۱

عدد، بردار، ماتریس و تنسور

زبان مشترک تمام محاسبات مدل.

Scalar یک عدد است؛ مثلاً دما یا یک امتیاز. بردار لیستی مرتب از اعداد است؛ مثلاً نمایش یک توکن با ۷۶۸ ویژگی آموخته‌شده. ماتریس جدولی دوبعدی از اعداد است. تنسور نام عمومی آرایه‌ای با هر تعداد بعد است.

ابعاد تنسور (shape)

scalar:  3.2               shape: []
vector:  [0.2, -1.1, 0.7] shape: [3]
matrix:  4 tokens × 8 dims shape: [4, 8]
batch:   32 × 4 × 8       shape: [32, 4, 8]

وزن و بایاس

weight مشخص می‌کند هر ورودی چه اندازه و با چه علامتی اثر بگذارد. bias یک offset قابل‌یادگیری است تا مدل مجبور نباشد همه‌چیز را از صفر عبور دهد.

y = Wx + b

ضرب داخلی: یک عدد برای میزان هم‌جهتی

دو بردار هم‌اندازه را عضو‌به‌عضو ضرب و جمع می‌کنیم. در Attention از این عملیات برای ساخت امتیاز شباهت Query و Key استفاده می‌شود.

[1, 2, 0] · [3, -1, 4] = (1×3) + (2×-1) + (0×4) = 1

ضرب داخلی بزرگ‌تر می‌تواند نشانهٔ هم‌جهتی بیشتر باشد، اما طول بردار هم روی آن اثر دارد. cosine similarity جهت را با نرمال‌کردن طول مقایسه می‌کند.

بُعد یعنی چه؟

وقتی می‌گوییم embedding دارای ۷۶۸ بُعد است، منظور ۷۶۸ محور آموخته‌شده است. معمولاً نمی‌توان گفت محور ۴۲ دقیقاً «رسمی‌بودن» است؛ معنا میان تعداد زیادی بُعد توزیع شده است.

چند مثال برای جاافتادن بردار و ماتریس

اگر یک چیز را با چند عدد توصیف کنیم، عملاً یک بردار ساخته‌ایم. برای یک خانه، اعداد می‌توانند متراژ، سن بنا، فاصله تا مرکز شهر و تعداد اتاق باشند. برای یک کلمه، اعداد مستقیم و انسانی نیستند؛ مدل خودش یاد می‌گیرد چه ویژگی‌هایی برای پیش‌بینی مفیدند.

  • بردار ساده: یک فیلم را با سه عدد توصیف کن: میزان کمدی، میزان هیجان، میزان جدی‌بودن. دو فیلمی که بردارهای نزدیک‌تری دارند احتمالاً حس مشابه‌تری می‌دهند.
  • ماتریس: اگر برای ۱۰۰ فیلم، هر کدام ۳ ویژگی داشته باشیم، یک جدول ۱۰۰ در ۳ داریم. همین ایده در مدل‌ها با هزاران یا میلیون‌ها ردیف و ستون اتفاق می‌افتد.
  • تنسور: اگر چند جمله داشته باشیم، هر جمله چند توکن داشته باشد و هر توکن یک بردار چندبعدی داشته باشد، دیگر فقط جدول دوبعدی نداریم؛ یک آرایهٔ چندبعدی داریم.

وقتی فرمول‌ها ترسناک می‌شوند، آن‌ها را به عملیات ساده برگردان: ضرب، جمع، مقایسه و تغییر شکل آرایه‌ها. بخش زیادی از شبکهٔ عصبی همین‌هاست، فقط در ابعاد بسیار بزرگ.

چرا مدل فقط با عدد کار می‌کند؟

پردازنده عملیات جمع و ضرب را روی آرایه‌های عددی بسیار سریع اجرا می‌کند. آموزش هم به تابع‌های پیوسته و قابل‌مشتق نیاز دارد؛ string خام چنین ساختاری ندارد.

۲

از مدل خطی تا نورون

کوچک‌ترین واحد محاسباتی را بدون استعارهٔ زیستی بفهمیم.

یک نورون مصنوعی چند ورودی را با وزن‌هایشان ترکیب می‌کند، بایاس را اضافه می‌کند و معمولاً نتیجه را از یک activation function عبور می‌دهد:

z = w₁x₁ + w₂x₂ + … + wₙxₙ + b     ;     a = activation(z)

مثلاً برای حدس‌زدن اینکه یک پیام مثبت است یا منفی، x₁ می‌تواند تعداد واژه‌های مثبت و x₂ تعداد واژه‌های منفی باشد. مدل هنگام training یاد می‌گیرد کدام ویژگی مهم‌تر است. نورون یک مغز کوچک یا محل ذخیرهٔ یک مفهوم کامل نیست؛ فقط یک محاسبهٔ پارامتری است.

پارامتر: مقداری که مدل از داده یاد می‌گیرد؛ مانند وزن و بایاس. Hyperparameter: انتخابی بیرونی مانند نرخ یادگیری، batch size یا تعداد لایه‌ها.

Forward Pass

حرکت از input به پیش‌بینی را forward pass می‌نامیم. هنوز چیزی یاد گرفته نشده؛ فقط با پارامتر‌های فعلی خروجی محاسبه شده است.

نورون را با چند مثال ببین

نورون یک تصمیم‌گیر کوچک نیست که «معنا» را بفهمد؛ یک محاسبه است. چند ورودی می‌گیرد، هر کدام را با وزن خودش ضرب می‌کند، بایاس را اضافه می‌کند و خروجی می‌دهد. اگر وزن یک ویژگی بزرگ‌تر باشد، آن ویژگی در خروجی اثر بیشتری دارد.

  • مثال پیام مثبت/منفی: اگر واژه‌های مثبت زیاد باشند، وزن مثبت خروجی را بالا می‌برد. اگر واژه‌های منفی زیاد باشند، وزن منفی خروجی را پایین می‌آورد یا به سمت کلاس منفی می‌برد.
  • مثال تصمیم ساده: برای تشخیص اینکه یک ایمیل تبلیغاتی است، ویژگی‌هایی مثل تعداد لینک، وجود کلمات تخفیف، و فرستندهٔ ناشناس می‌توانند ورودی باشند. نورون یاد می‌گیرد هر نشانه چقدر مهم است.
  • نقش بایاس: بایاس مثل نقطهٔ شروع است. حتی اگر همهٔ ورودی‌ها صفر باشند، مدل ممکن است یک تمایل پایه داشته باشد؛ این تمایل با بایاس نمایش داده می‌شود.

پس وقتی می‌بینی y = Wx + b، آن را این‌طور بخوان: «ویژگی‌ها را با اهمیتشان ترکیب کن، کمی جابه‌جایی پایه اضافه کن، خروجی خام بساز.»

آیا هر نورون یک کلمه یا مفهوم مشخص را تشخیص می‌دهد؟

گاهی واحدهایی به pattern خاص حساس می‌شوند، اما representation معمولاً distributed است. نسبت‌دادن یک مفهوم انسانی ثابت به هر نورون مدل ذهنی قابل‌اعتمادی نیست.

۳

شبکهٔ عصبی و لایه‌ها

چرا یک خط کافی نیست و «عمیق» چه معنایی دارد؟

لایهٔ ورودی
x→Linear + Activation→Hidden representation→Output logits

ترکیب چند تابع خطی بدون activation هنوز یک تابع خطی است. غیرخطی‌بودن اجازه می‌دهد شبکه رابطه‌های پیچیده را مدل کند. Deep یعنی چندین مرحلهٔ representation پشت سر هم قرار گرفته‌اند.

لایه

لایه یک مرحلهٔ مشخص از پردازش است: تنسور را می‌گیرد، روی آن محاسبه انجام می‌دهد و تنسور تازه‌ای برمی‌گرداند. بعضی لایه‌ها پارامتر آموختنی دارند، مثل لایهٔ خطی؛ بعضی فقط شکل یا مقیاس داده را عوض می‌کنند. در Transformer، Attention و Feed-Forward معمولاً زیرلایه‌های یک بلوک بزرگ‌تر هستند.

Representation

شکل عددی‌ای که مدل در یک مرحله برای بیان اطلاعات ساخته است.

تعداد پارامترها

تعداد وزن‌ها و بایاس‌های قابل‌یادگیری. 7B تقریباً یعنی هفت میلیارد پارامتر، نه هفت میلیارد خط کد.

معماری

نقشهٔ اتصال لایه‌ها و جریان داده. Training پارامترها را تعیین می‌کند؛ معماری ظرف محاسبات است.

تعمیم و Overfitting

هدف حفظ‌کردن training set نیست؛ مدل باید روی example ندیده خوب کار کند. اگر training loss پایین ولی زیان اعتبارسنجی بالا باشد، احتمال overfitting وجود دارد. تقسیم train/validation/test کمک می‌کند یادگیری را از حفظ‌کردن جدا کنیم.

لایه را دقیق‌تر بفهمیم

وقتی می‌گوییم «لایه»، منظورمان یک مرحله از خط تولید عددی مدل است. ورودی و خروجی هر لایه معمولاً تنسور است، اما معنی تنسور در هر مرحله فرق می‌کند. اول مسیر، تنسور ممکن است نمایش عددی توکن‌ها باشد؛ وسط مسیر، همان تنسور تبدیل به نمایش غنی‌تر متن می‌شود؛ آخر مسیر، تنسور به امتیاز توکن‌های بعدی نزدیک می‌شود.

  • لایهٔ خطی: شبیه یک ترکیب وزن‌دار است. ورودی را با ماتریس وزن‌ها ضرب می‌کند و بایاس را اضافه می‌کند. این لایه پارامتر آموختنی دارد.
  • تابع فعال‌سازی: بعد از یک تبدیل خطی می‌آید تا غیرخطی‌بودن اضافه کند. همیشه به اندازهٔ لایهٔ خطی پارامتر ندارد، اما رفتار مدل را عوض می‌کند.
  • لایهٔ Attention: برای هر توکن تصمیم می‌گیرد از بقیهٔ توکن‌های مجاز چقدر اطلاعات بگیرد. خروجی هنوز تنسور است، اما هر موقعیت با زمینهٔ اطرافش غنی‌تر شده است.
  • لایهٔ Feed-Forward: بعد از Attention روی هر موقعیت جداگانه پردازش غیرخطی انجام می‌دهد؛ انگار هر توکن فرصت دارد نمایش خودش را دوباره بازنویسی کند.

پس «لایه» الزاماً یک جعبهٔ یکسان نیست. بیشتر شبیه اسم عمومی برای مرحله‌های پردازش است. «معماری» می‌گوید این مرحله‌ها با چه ترتیبی کنار هم چیده شده‌اند؛ «پارامترها» مقدارهای قابل‌یادگیری داخل بعضی از همین مرحله‌ها هستند.

چرا شبکهٔ چندلایه لازم می‌شود؟

یک مدل خطی فقط می‌تواند رابطه‌های ساده را خوب بگیرد. اما خیلی از مسائل واقعی ترکیبی‌اند: یک نشانه به‌تنهایی کافی نیست، ولی ترکیب چند نشانه معنی می‌سازد. لایه‌های میانی کمک می‌کنند مدل از ویژگی‌های خام، نمایش‌های پیچیده‌تر بسازد.

  • مثال تصویر: لایه‌های اولیه شاید لبه و رنگ را تشخیص دهند؛ لایه‌های بعدی ترکیب لبه‌ها را به شکل، و شکل‌ها را به شیء نزدیک کنند.
  • مثال زبان: یک لایه شاید رابطهٔ نزدیک میان واژه‌ها را بگیرد؛ لایهٔ بعدی ساختار جمله را بهتر بفهمد؛ لایه‌های بالاتر الگوی معنایی و سبک پاسخ را شکل دهند.
  • مثال overfitting: دانش‌آموزی که فقط جواب نمونه‌سؤال‌ها را حفظ کرده، در امتحان جدید گیر می‌کند. مدل هم اگر فقط دادهٔ آموزش را حفظ کند، روی دادهٔ جدید خوب کار نمی‌کند.

کلمهٔ «عمیق» یعنی مدل چند مرحله فرصت دارد نمایش ورودی را بهتر کند. هر مرحله قرار نیست مفهوم انسانی واضحی داشته باشد؛ مهم این است که برای کاهش زیان مفید باشد.

Training: زیان، گرادیان و Backpropagation

مدل دقیقاً چگونه وزن‌هایش را تغییر می‌دهد؟

  1. Forward pass: مدل با وزن‌های فعلی پیش‌بینی می‌سازد.
  2. Loss: نشان می‌دهد پیش‌بینی چقدر با مقدار هدف فاصله دارد.
  3. Backward pass: backpropagation سهم هر پارامتر در زیان را با chain rule محاسبه می‌کند.
  4. گام بهینه‌ساز: پارامتر‌ها کمی در جهت کاهش زیان تغییر می‌کنند.
  5. این چرخه روی batchهای فراوان تکرار می‌شود.
w_new = w_old − learning_rate × ∂Loss/∂w

gradient برداری از مشتق‌هاست: اگر هر پارامتر کمی تغییر کند، زیان با چه جهت و شدتی تغییر می‌کند؟ gradient descent در خلاف جهت گرادیان حرکت می‌کند. learning rate اندازهٔ گام است؛ گام خیلی بزرگ می‌تواند training را ناپایدار و گام خیلی کوچک آن را کند کند.

Training را مثل اصلاح تدریجی بخوان

مدل در آغاز معمولاً جواب‌های خوبی نمی‌دهد، چون پارامترهایش هنوز تنظیم نشده‌اند. در هر دور، یک پیش‌بینی می‌سازد، با جواب درست مقایسه می‌شود، زیان محاسبه می‌شود، سپس گرادیان نشان می‌دهد کدام پارامترها باید کم یا زیاد شوند. این چرخه هزاران یا میلیون‌ها بار تکرار می‌شود.

  • مثال هدف‌گیری: اگر توپ را همیشه کمی سمت راست می‌زنی، بازخورد می‌گوید دفعهٔ بعد کمی به چپ اصلاح کن. گرادیان هم جهت اصلاح را می‌گوید، نه جواب نهایی را.
  • مثال نرخ یادگیری: اگر گام اصلاح خیلی بزرگ باشد، از هدف رد می‌شوی و نوسان می‌کنی. اگر خیلی کوچک باشد، رسیدن به جواب خوب خیلی طول می‌کشد.
  • مثال batch: به‌جای اینکه بعد از هر نمونه فوراً اصلاح کنی، چند نمونه را با هم می‌بینی و میانگین جهت اصلاح را می‌گیری تا تصمیم پایدارتر شود.

Backpropagation فقط روش حساب‌کردن سهم هر پارامتر در زیان است. خود «حرکت‌دادن پارامترها» کار بهینه‌ساز است.

Backpropagation با گرادیان کاهشی یکی است؟

نه. Backpropagation گرادیان‌ها را به‌شکل کارآمد محاسبه می‌کند؛ گرادیان کاهشی یا بهینه‌ساز از آن‌ها برای update کردن پارامتر‌ها استفاده می‌کند.

Logit، Softmax و Cross-Entropy

پل میان امتیاز خام، احتمال و انتخاب توکن.

Logit چیست؟

خروجی خام مدل، برای هر class یا توکن، logit نام دارد. logit احتمال نیست؛ می‌تواند منفی باشد، می‌تواند بزرگ‌تر از ۱ باشد، و مجموع logitها هم محدودیت خاصی ندارد.

softmax(zᵢ) = exp(zᵢ) / Σⱼ exp(zⱼ)

Softmax سه کار می‌کند: اول، با exponential همهٔ مقدارها را مثبت می‌کند؛ دوم، امتیاز بزرگ‌تر را برجسته‌تر می‌کند؛ سوم، با تقسیم بر مجموع، خروجی‌ها را به احتمال‌هایی تبدیل می‌کند که جمعشان ۱ است.

مثال دستی

برای logits برابر [2, 1, 0]، مقدارهای نمایی تقریباً [7.39, 2.72, 1] و مجموع 11.11 است؛ پس احتمال‌ها حدود [0.665, 0.245, 0.090] می‌شوند.

Numerical stability: در کد واقعی ابتدا بزرگ‌ترین logit را از همه کم می‌کنیم. Softmax تغییر نمی‌کند، ولی از overflow در exp جلوگیری می‌شود.

Temperature چیست؟

Temperature یعنی «دکمهٔ میزان جسارت در انتخاب از بین گزینه‌ها». مدل، بعد از دیدن متن، برای توکن بعدی چندین گزینه با امتیازهای مختلف دارد. اگر همیشه فقط «بالاترین امتیاز» را برداریم، خروجی خشک‌تر و تکرارپذیرتر می‌شود؛ اگر اجازه بدهیم گاهی گزینه‌های کمی پایین‌تر هم انتخاب شوند، خروجی متنوع‌تر می‌شود. Temperature، همین مقدار آزادی را کنترل می‌کند.

softmax_with_temperature(zᵢ) = exp(zᵢ / T) / Σⱼ exp(zⱼ / T)

در فرمول بالا، T همان temperature است. قبل از اجرای Softmax، هر logit بر T تقسیم می‌شود. اگر T = 1 باشد، توزیع همان حالت عادی است؛ اگر T کمتر از ۱ باشد، اختلاف امتیازها بزرگ‌تر حس می‌شود، و مدل بیشتر به گزینهٔ اول می‌چسبد؛ اگر T بیشتر از ۱ باشد، اختلاف امتیازها کم‌رنگ‌تر می‌شود، و گزینه‌های بیشتری شانس انتخاب پیدا می‌کنند.

T = 0 یا نزدیک صفر

در بسیاری از ابزارها یعنی تقریباً همیشه محتمل‌ترین گزینه را انتخاب کن. مناسب پاسخ‌های دقیق، قالب‌دار و کم‌تنوع؛ اما تضمین نمی‌کند پاسخ درست باشد.

T = 1

حالت معمول؛ توزیع احتمال تقریباً همان چیزی است که از logitهای مدل بیرون آمده است.

T > 1

انتخاب آزادتر می‌شود. برای ایده‌پردازی، متن خلاقانه یا چند پیشنهاد متفاوت مفید است؛ ولی خطر پاسخ‌های عجیب یا کم‌دقت بیشتر می‌شود.

یک مثال روزمره: فرض کن سه جواب ممکن داریم؛ «بله» با امتیاز زیاد، «شاید» با امتیاز متوسط، و «نه» با امتیاز کم. temperature پایین، مثل این است که بگویی: «ریسک نکن، همان گزینهٔ اول را بگو.» temperature بالا، مثل این است که بگویی: «اگر گزینه‌های دیگر هم کمی معقول‌اند، گاهی آن‌ها را هم امتحان کن.»

نکتهٔ خیلی مهم: Temperature دانش مدل را زیاد یا کم نمی‌کند. اگر مدل چیزی را نمی‌داند، بالا بردن temperature آن را دانا نمی‌کند؛ فقط انتخاب را متنوع‌تر و گاهی پرریسک‌تر می‌کند. پایین آوردنش هم پاسخ را حقیقت‌سنجی نمی‌کند؛ فقط انتخاب را محافظه‌کارتر می‌کند.

آزمایش تعاملی Softmax و Temperature

برای دیدن اثرش، مقدار logits را روی 2, 1, 0 بگذار. با T = 0.5، احتمال گزینهٔ اول خیلی غالب می‌شود؛ با T = 2، سه گزینه به هم نزدیک‌تر می‌شوند. یعنی temperature مثل ذره‌بین، یا پخش‌کنندهٔ اختلاف‌ها، عمل می‌کند.

Cross-Entropy چه می‌سنجد؟

Cross-Entropy یک روش اندازه‌گیری «بدیِ پیش‌بینی» است. بعد از Softmax، مدل برای هر گزینه یک احتمال می‌دهد؛ اما هنگام آموزش، ما می‌دانیم جواب درست کدام گزینه است. سؤال Cross-Entropy این است: مدل، برای جواب درست، چقدر احتمال گذاشت؟

فرض کن سه گزینه داریم، و جواب درست، گزینهٔ دوم است. اگر مدل احتمال‌ها را این‌طور بدهد: [0.10, 0.80, 0.10]، یعنی برای جواب درست، ۸۰٪ احتمال گذاشته؛ پس «جریمه» یا «زیان» کم است. اما اگر احتمال‌ها این‌طور باشد: [0.80, 0.10, 0.10]، مدل، با اعتماد زیاد، گزینهٔ غلط را ترجیح داده؛ پس زیان زیاد می‌شود.

پس، در حالت ساده، اگر مقدار هدف صحیح class شمارهٔ ۲ باشد، فقط احتمال همان گزینهٔ درست را نگاه می‌کنیم: p₂. زیان برابر است با -log(p₂). «احتمال زیاد» برای جواب درست، یعنی «زیان کوچک»؛ «احتمال کم» برای جواب درست، یعنی «زیان بزرگ». هرچه p₂ به ۱ نزدیک‌تر باشد، زیان به صفر نزدیک‌تر می‌شود؛ هرچه p₂ به صفر نزدیک‌تر باشد، زیان بزرگ‌تر می‌شود.

CrossEntropy(target=k) = −log(softmax(logits)ₖ)
احتمال مدل برای جواب درستزیان تقریبیبرداشت ساده
p = 0.90-log(0.90) ≈ 0.105مدل تقریباً جواب درست را جدی گرفته؛ جریمه کم است.
p = 0.50-log(0.50) ≈ 0.693مدل دودل است؛ جریمه متوسط است.
p = 0.10-log(0.10) ≈ 2.303مدل جواب درست را تقریباً کنار گذاشته؛ جریمه زیاد است.
p = 0.01-log(0.01) ≈ 4.605مدل با اطمینان از جواب درست دور شده؛ جریمه خیلی زیاد است.
شهود اصلی: Cross-Entropy همهٔ گزینه‌ها را جداگانه قضاوت نمی‌کند؛ تمرکز اصلی‌اش، روی احتمال گزینهٔ درست است. اگر مدل به جواب درست احتمال بیشتری بدهد، زیان کمتر می‌شود؛ و آموزش، مدل را به سمت همین رفتار فشار می‌دهد.
چرا از log استفاده می‌کنیم؟

log باعث می‌شود اشتباه‌های با اعتماد بالا، خیلی بیشتر جریمه شوند. فرق بین ۹۰٪ و ۸۰٪ مهم است، اما فاجعه نیست؛ ولی اگر مدل، برای جواب درست، فقط ۱٪ احتمال بگذارد، یعنی تقریباً آن را حذف کرده، و باید جریمهٔ بزرگی بگیرد. همچنین، log از نظر ریاضی، برای جمع‌کردن زیان روی نمونه‌های زیاد، رفتار مناسبی دارد.

در مدل زبانی، جواب درست یعنی چه؟

در آموزش مدل زبانی، جواب درست معمولاً «توکن بعدی واقعی در متن آموزشی» است. مثلاً اگر متن آموزشی بگوید «امروز هوا خیلی ... سرد»، در آن موقعیت، توکن بعدیِ هدف «سرد» است. مدل برای همهٔ توکن‌های واژگان احتمال می‌سازد؛ اما Cross-Entropy نگاه می‌کند که برای توکن درست، چقدر احتمال گذاشته است.

Softmax را با چند زاویه ببین

Softmax خودش تصمیم‌گیر نهایی نیست؛ یک تبدیل است. ورودی آن امتیازهای خام‌اند و خروجی آن توزیعی است که جمعش ۱ می‌شود. اگر یک امتیاز از بقیه خیلی بزرگ‌تر باشد، خروجی بسیار متمرکز می‌شود؛ اگر امتیازها نزدیک باشند، خروجی پخش‌تر می‌شود.

  • گزینه‌های نزدیک: اگر امتیازها [1.1, 1.0, 0.9] باشند، مدل بین گزینه‌ها خیلی مطمئن نیست و احتمال‌ها نسبتاً نزدیک می‌مانند.
  • گزینهٔ غالب: اگر امتیازها [8, 1, 0] باشند، گزینهٔ اول تقریباً همهٔ احتمال را می‌گیرد. اینجا خروجی تیز و کم‌تنوع است.
  • Temperature: دمای پایین اختلاف‌ها را پررنگ‌تر می‌کند؛ دمای بالا اختلاف‌ها را کم‌رنگ‌تر می‌کند. دانش مدل عوض نمی‌شود، فقط روش انتخاب از همان امتیازها عوض می‌شود.

نکتهٔ مهم: احتمال Softmax احتمال «درست‌بودن در جهان واقعی» نیست. فقط احتمال نسبی گزینه‌ها در ذهن عددی مدل و در همان لحظه است.

آیا خروجی Softmax «اعتماد واقعی» مدل است؟

نه لزوماً. احتمال مدل ممکن است calibration خوبی نداشته باشد. ۹۰٪ در توزیع خروجی تضمین نمی‌کند پاسخ در جهان واقعی ۹۰٪ درست است.

embedding(token_id) = row[token_id] from E ∈ ℝ^(vocab_size × d_model)

Word2Vec چه ایده‌ای اضافه کرد؟

Word2Vec embedding را از یک task جانبی یاد می‌گیرد: در Skip-gram از کلمهٔ مرکزی همسایه‌ها پیش‌بینی می‌شوند و در CBOW از همسایه‌ها کلمهٔ مرکزی. واژه‌هایی با context مشابه بردارهای نزدیک‌تری پیدا می‌کنند. محدودیت: یک واژه معمولاً یک بردار static دارد و چندمعنایی را با context حل نمی‌کند.

Subword Tokenization

تقسیم به subword میان vocabulary کاملاً کلمه‌ای و character-level تعادل ایجاد می‌کند: واژهٔ نادر می‌تواند از بخش‌های آشناتر ساخته شود. BPE یکی از روش‌های تاریخی مهم این مسیر است. مرز توکن همیشه با مرز واژه یا معنا یکی نیست.

توکن ≠ word: هزینه، context length و احتمال خروجی بر حسب توکن محاسبه می‌شوند. یک واژهٔ فارسی ممکن است چند توکن شود.

چرا توکن‌سازی برای فهم LLM حیاتی است؟

مدل مستقیماً با کلمه کار نمی‌کند؛ با شناسهٔ توکن کار می‌کند. همین نکته روی هزینه، طول متن قابل‌پردازش، سرعت، و حتی کیفیت پاسخ اثر دارد. گاهی یک واژهٔ کوتاه یک توکن است، گاهی یک واژهٔ ناآشنا یا فارسی چند توکن می‌شود.

  • شناسه معنا نیست: اگر شناسهٔ «کتاب» ۵۰۰ و شناسهٔ «دفتر» ۹۰۰ باشد، نزدیکی یا دوری عددها معنی زبانی ندارد. معنا بعداً در embedding ساخته می‌شود.
  • One-Hot: فقط می‌گوید کدام توکن حاضر است؛ دربارهٔ شباهت واژه‌ها چیزی نمی‌گوید. برای همین به embedding نیاز داریم.
  • Embedding: به جای یک خانهٔ روشن در بردار عظیم، برای هر توکن یک بردار فشرده و آموخته‌شده می‌سازد که در ترکیب با متن معنا پیدا می‌کند.

اگر یک پاسخ عجیب دیدی، یکی از چیزهایی که می‌تواند دخیل باشد مرزبندی توکن‌هاست؛ مخصوصاً در زبان‌هایی که فاصله، نیم‌فاصله یا شکل نوشتاری متنوع دارند.

۸

Sequence، RNN و گلوگاه Context

چرا قبل از Transformer پردازش ترتیبی مسئله‌ساز بود؟

معنای زبان به ترتیب و context وابسته است. RNN در هر time step ورودی فعلی و hidden state قبلی را ترکیب می‌کند:

hₜ = f(xₜ, hₜ₋₁)

این state خلاصه‌ای از گذشته است. LSTM و GRU با gateها جریان حافظه و گرادیان را بهتر کردند، اما سه محدودیت اصلی باقی ماند:

Sequential compute

برای محاسبهٔ h₁₀ ابتدا h₉ لازم است؛ موازی‌سازی دشوار می‌شود.

Long dependency

رابطهٔ دو توکن دور باید از stateهای میانی زیادی عبور کند.

Fixed bottleneck

Encoder کلاسیک کل ورودی را به یک بردار ثابت برای Decoder تحویل می‌داد.

Attention ابتدا برای رفع گلوگاه آخر در Neural Machine Translation مطرح شد: Decoder به‌جای تکیه بر یک خلاصهٔ ثابت، در هر گام به همهٔ stateهای Encoder نگاه می‌کند.

چرا ترتیب جمله دردسر درست می‌کند؟

در زبان، جای کلمه‌ها مهم است. «علی به سارا کتاب داد» با «سارا به علی کتاب داد» کلمات مشابه دارد، اما نقش‌ها عوض شده‌اند. مدل باید هم ترتیب را بفهمد، هم رابطهٔ کلمه‌های دور از هم را نگه دارد.

  • مشکل حافظهٔ فشرده: اگر کل جملهٔ بلند را مجبور کنیم در یک بردار ثابت خلاصه شود، بخشی از اطلاعات ظریف از دست می‌رود.
  • مشکل محاسبهٔ ترتیبی: در RNN برای رسیدن به گام دهم باید گام‌های قبل طی شوند؛ این برای آموزش روی دادهٔ عظیم کند است.
  • مشکل وابستگی دور: اگر فاعل اول جمله باشد و فعل خیلی آخر جمله بیاید، رابطه باید از مسیر طولانی عبور کند. Attention این مسیر را کوتاه‌تر می‌کند.

پس Attention فقط یک فرمول شیک نبود؛ پاسخی به یک محدودیت عملی در مدل‌های ترتیبی بود.

۹

Attention: جست‌وجوی نرم در حافظه

Q، K، V و Softmax را از یک مثال ملموس بسازیم.

Query بیان می‌کند «چه می‌خواهم؟»، هر Key می‌گوید «این بخش با چه نشانه‌ای قابل‌پیداکردن است؟» و Value محتوایی است که در صورت مرتبط‌بودن برداشته می‌شود. برخلاف جست‌وجوی سخت که معمولاً یک مورد مشخص را برمی‌گرداند، Attention معمولاً همهٔ Valueها را با وزن متفاوت ترکیب می‌کند.

Query (Q)

نیاز representation فعلی؛ دنبال چه رابطه‌ای هستم؟

Key (K)

نمایهٔ قابل‌مقایسهٔ هر موقعیت برای محاسبهٔ relevance.

Value (V)

اطلاعاتی که پس از تعیین وزن واقعاً تجمیع می‌شود.

  1. از representation ورودی با ماتریس‌های آموختنی، Q و K و V بساز.
  2. برای هر Query، با ضرب داخلی همهٔ Keyها امتیاز بساز.
  3. امتیاز را بر √dₖ تقسیم کن تا دامنه کنترل شود.
  4. با Softmax، امتیازها را به attention weight تبدیل کن.
  5. جمع وزن‌دار Valueها را خروجی بگیر.
Attention(Q,K,V) = softmax(QKᵀ / √dₖ) V

اگر امتیاز‌های یک Query برای سه توکن برابر [2, 1, 0] باشند، Softmax تقریباً وزن‌های [0.665, 0.245, 0.090] می‌سازد. خروجی 0.665V₁ + 0.245V₂ + 0.090V₃ است؛ مدل فقط یک توکن را انتخاب نکرده است.

چرا مقیاس‌بندی؟

با بزرگ‌شدن بُعد، ضرب‌های داخلی می‌توانند magnitude بزرگی پیدا کنند. Softmax روی اختلاف‌های بزرگ اشباع و گرادیان کوچک می‌شود. تقسیم بر ریشهٔ بُعد کلید، واریانس امتیازها را کنترل می‌کند.

Q/K/V را با مثال عمومی بفهم

فرض کن در یک متن، واژهٔ «آن» آمده و مدل باید بفهمد «آن» به چه چیزی اشاره می‌کند. Query نیاز موقعیت فعلی است: «مرجع من چیست؟» Keyهای بقیهٔ کلمه‌ها نشانه‌های قابل‌مقایسه‌اند، و Valueها محتوایی هستند که اگر مرتبط باشند وارد نمایش جدید می‌شوند.

  • سؤال و جواب: در پرسش «پایتخت فرانسه کجاست؟»، توکن‌های مربوط به «فرانسه» و «پایتخت» باید وزن بیشتری در ساخت پاسخ بگیرند.
  • ضمیر: در جملهٔ «مریم کتاب را برداشت چون آن را لازم داشت»، مدل باید ارتباط «آن» با «کتاب» را پیدا کند.
  • ترجمه: هنگام ساختن کلمهٔ مقصد، مدل شاید به چند کلمهٔ مبدأ هم‌زمان توجه کند، نه فقط به یک کلمه.

اشتباه رایج: Attention weight را توضیح کامل فکر مدل بدانیم. این وزن‌ها سرنخ‌اند، اما همیشه علت کامل رفتار مدل نیستند.

Q/K/V خود توکن نیستند: projectionهای متفاوتی از representation هستند: Q=XWQ, K=XWK, V=XWV.

ترجمهٔ مفهومی «Attention Is All You Need»

مقالهٔ Vaswani و همکاران، ۲۰۱۷؛ شرح محتوایی به‌جای ترجمهٔ کلمه‌به‌کلمه.

ایدهٔ مرکزی مقاله: برای sequence transduction لازم نیست recurrence یا convolution هستهٔ ارتباط میان توکن‌ها باشد. می‌توان معماری Encoder–Decoder را بر Attention بنا کرد، موقعیت‌های هر لایه را موازی‌تر محاسبه کرد و مسیر ارتباط توکن‌های دور را کوتاه کرد.

مسئله‌ای که مقاله از آن شروع می‌کند

مدل‌های ترجمهٔ قوی آن زمان عمدتاً RNN/CNN بودند. RNN محاسبه را ترتیبی می‌کرد و dependency دور مسیر بلندی داشت. Attention پیش‌تر در کنار RNN موفق شده بود، اما این مقاله پرسید: اگر Attention را از جزء کمکی به سازوکار اصلی تبدیل کنیم چه می‌شود؟ پاسخ معماری Transformer بود.

Abstract به زبان ساده

نویسندگان یک Encoder–Decoder بدون recurrence و convolution پیشنهاد کردند که برای ارتباط میان موقعیت‌ها از Attention استفاده می‌کند. در آزمایش‌های ترجمهٔ انگلیسی–آلمانی و انگلیسی–فرانسوی، مدل آن‌ها کیفیت قوی و training موازی‌پذیرتری ارائه کرد. مقاله همچنین تعمیم معماری را روی parsing بررسی کرد.

توزیع خروجی

Encoder چه می‌کند؟

هر لایهٔ Encoder در مقاله دو زیرلایه دارد: Multi-Head Self-Attention و یک position-wise Feed-Forward Network. دور هر زیرلایه یک residual connection و سپس نرمال‌سازی لایه قرار می‌گیرد. هر توکن از توکن‌های دیگر همان ورودی information می‌گیرد.

Decoder چه می‌کند؟

Decoder سه زیرلایه دارد: masked Self-Attention روی توکن‌های خروجی قبلی، Cross-Attention که Query را از Decoder و Key/Value را از Encoder می‌گیرد، و Feed-Forward. Mask اجازه نمی‌دهد موقعیت خروجی پاسخ آینده را ببیند.

Scaled Dot-Product Attention

مقاله Queryها را با Keyها ضرب می‌کند، scale را اعمال می‌کند، mask احتمالی را پیش از Softmax وارد می‌کند و وزن‌های حاصل را روی Valueها می‌زند. ماتریس ارتباط همهٔ Queryها با همهٔ Keyها هم‌زمان ساخته می‌شود.

Multi-Head یعنی چه؟

به‌جای یک Attention، Q/K/V به چند فضای کوچک‌تر project می‌شوند. هر head Attention مستقل خود را محاسبه می‌کند؛ خروجی headها concatenate و با projection نهایی مخلوط می‌شود. مدل می‌تواند چند نوع رابطه را در subspaceهای مختلف دنبال کند، اما هر head الزاماً یک مفهوم انسانی ثابت ندارد.

headᵢ = Attention(QWᵢQ, KWᵢK, VWᵢV)
MultiHead = Concat(head₁,…,headₕ)Wᴼ

موقعیت چرا لازم است؟

Self-Attention خام ترتیب را از index نمی‌فهمد. مقاله sinusoidal positional encoding را به embedding ورودی اضافه کرد. Transformerهای بعدی روش‌های دیگری مانند موقعیت آموخته‌شده یا موقعیت چرخشی به‌کار بردند؛ اصل نیاز به موقعیت پابرجاست.

Feed-Forward، Residual و نرمال‌سازی

Attention میان توکن‌ها اطلاعات جابه‌جا می‌کند. FFN روی هر موقعیت یک تبدیل nonlinear انجام می‌دهد. Residual مسیر مستقیم عبور اطلاعات می‌سازد و نرمال‌سازی، آموزش را پایدارتر می‌کند. پس عنوان مقاله به معنی حذف همهٔ اجزای غیر Attention نیست.

Embedding تا Vocabulary

در انتهای Decoder، linear projection برای هر توکن واژگان logit می‌سازد و توزیع Softmax خروجی را تولید می‌کند. هنگام training، sequence هدف یک موقعیت shift می‌شود: prefix ورودی است و توکن بعدی برچسب.

چرا path length مهم بود؟

در RNN انتقال اطلاعات از ابتدای sequence به انتها چندین step داشت. در Self-Attention، هر موقعیت در یک لایه مستقیماً با هر موقعیت مجاز امتیاز دارد. هزینهٔ مهم آن، ماتریس توجه با رشد تقریباً quadratic نسبت به sequence length است.

مقاله چه چیزی نمی‌گوید؟

  • مقاله دربارهٔ chatbot، instruction following، RLHF، agent یا استفاده از ابزار نیست.
  • ثابت نمی‌کند recurrence برای همهٔ مسئله‌ها بی‌ارزش شده است.
  • نمی‌گوید Attention توضیح‌پذیری کامل فراهم می‌کند.
  • Transformerهای امروز جزئیات اجرایی متفاوتی با نسخهٔ original دارند.
خلاصهٔ یک‌دقیقه‌ای: مقاله گلوگاه پردازش ترتیبی را هدف گرفت؛ با Self-Attention ارتباط مستقیم میان توکن‌ها ساخت؛ Multi-Head چند projection موازی داد؛ موقعیت ترتیب را وارد کرد؛ Encoder/Decoder با FFN، residual و نرمال‌سازی کامل شدند؛ Linear + Softmax، توکن خروجی را پیش‌بینی کرد.
چرا عنوان «Attention Is All You Need» کمی اغراق‌آمیز است؟

چون مدل علاوه بر Attention به embedding، positional encoding، FFN، residual، نرمال‌سازی، objective، بهینه‌ساز و داده نیاز دارد. عنوان به حذف recurrence/convolution از هستهٔ sequence modeling اشاره می‌کند.

Causal Mask

در موقعیت شمارهٔ t، امتیاز‌های آینده با مقدار بسیار منفی mask می‌شوند تا پس از وزن Softmax تقریباً صفر بگیرند. بدون mask، مدل هنگام training پاسخ آینده را می‌بیند.

Multi-Head و ابعاد

اگر d_model=512 و h=8 باشد، معمولاً هر head بعد ۶۴ دارد. Q/K/V برای همهٔ توکن‌ها ساخته و به headها reshape می‌شوند. خروجی headها دوباره به بُعد اصلی برمی‌گردد.

Residual Stream

می‌توان representation هر توکن را یک stream در نظر گرفت. Attention و MLP تغییراتی به آن اضافه می‌کنند. Residual باعث می‌شود هر زیرلایه لازم نباشد representation را از صفر بازسازی کند.

یک بلوک Transformer را مثل ایستگاه پردازش ببین

هر توکن وارد بلوک می‌شود، اول با بقیهٔ توکن‌های مجاز ارتباط می‌گیرد، بعد نمایش خودش را با یک شبکهٔ کوچک‌تر در همان موقعیت تغییر می‌دهد. اتصال residual باعث می‌شود اطلاعات قبلی کامل پاک نشود؛ تغییرات جدید به جریان قبلی اضافه می‌شوند.

  • Causal Mask: اگر مدل هنگام آموزش جواب آینده را ببیند، تقلب کرده است. ماسک باعث می‌شود فقط گذشته و موقعیت فعلی دیده شود.
  • Multi-Head: چند نگاه هم‌زمان است؛ یک نگاه شاید رابطهٔ ضمیر را بگیرد، یکی نزدیکی موضوعی، یکی نشانهٔ ساختار جمله. البته این تفسیر همیشه قطعی نیست.
  • MLP / FFN: بعد از جابه‌جایی اطلاعات میان توکن‌ها، هر موقعیت یک تبدیل غیرخطی جدا می‌گیرد تا نمایش خودش غنی‌تر شود.

اگر معماری را گم کردی، فقط این چرخه را حفظ کن: ارتباط میان توکن‌ها، پردازش داخل هر توکن، اضافه‌کردن به جریان قبلی، تکرار در لایه‌های بعدی.

از Transformer تا LLM

Pre-training، objective و رفتاری که از scale پدیدار می‌شود.

Pre-training

در decoder-only language model، متن به exampleهای فراوان پیش‌بینی توکن بعدی تبدیل می‌شود. برچسب از خود متن می‌آید، بنابراین روش self-supervised است. مدل برای کاهش Cross-Entropy مجبور می‌شود الگوهای syntax، semantics، سبک و facts موجود در داده را در پارامتر‌هایش فشرده کند.

P(x₁,…,xₙ) = ∏ₜ P(xₜ | x₁,…,xₜ₋₁)

BERT چه تفاوتی دارد؟

BERT اصلی Encoder-only و bidirectional است. بخشی از توکن‌ها در Masked Language Modeling پنهان/خراب می‌شوند و مدل با context چپ و راست آن‌ها را بازسازی می‌کند. interface پیش‌فرضش تولید autoregressive آزاد نیست.

Pre-training

یادگیری عمومی از corpus بزرگ؛ بسیار پرهزینه و طولانی.

Fine-tuning / Alignment

تطبیق behavior یا task با dataset کوچک‌تر.

Inference

استفاده از پارامتر‌های ثابت برای پردازش prompt و تولید output.

Context Window و حافظهٔ پارامترها

Context window فضای موقت توکن‌های همین request است. پارامتر‌ها الگوهای فشردهٔ training هستند. افزودن سند به prompt با تغییر وزن‌ها یکی نیست؛ Retrieval اطلاعات را موقتاً در context می‌آورد، Fine-tuning behavior را در پارامتر‌ها تغییر می‌دهد.

LLM دقیقاً چه چیزی را یاد گرفته است؟

مدل زبانی در آموزش بارها با این تمرین روبه‌رو می‌شود: «با دیدن متن قبلی، توکن بعدی را حدس بزن.» این تمرین ساده، مدل را مجبور می‌کند چیزهای زیادی را غیرمستقیم یاد بگیرد: دستور زبان، سبک نوشتن، رابطهٔ مفاهیم، الگوهای استدلالی رایج و بخشی از دانسته‌های موجود در داده.

  • دانش در پارامترها: چیزی است که مدل در وزن‌هایش فشرده کرده و بدون سند تازه می‌تواند از آن استفاده کند؛ اما ممکن است قدیمی یا ناقص باشد.
  • دانش در context: چیزی است که همین حالا در prompt یا فایل/سند داده‌ایم. این حافظه موقت‌تر اما قابل‌کنترل‌تر است.
  • Fine-tuning: بیشتر برای تغییر رفتار، سبک یا مهارت روی نمونه‌های تکرارشونده مناسب است؛ برای دانش تازهٔ مدام‌تغییر، معمولاً Retrieval بهتر است.

پس LLM پایگاه داده نیست. یک مدل پیش‌بینی توکن است که به دلیل مقیاس زیاد، رفتارهای زبانی و دانشی پیچیده از خود نشان می‌دهد.

Inference و Decoding

چگونه توزیع به متن خروجی تبدیل می‌شود؟

  1. Prompt tokenize و forward pass اجرا می‌شود (prefill).
  2. از logits آخرین موقعیت یک توکن انتخاب می‌شود.
  3. توکن انتخابی به context افزوده و گام بعد اجرا می‌شود (decode).
  4. این حلقه تا توکن توقف یا محدودیت خروجی ادامه می‌یابد.

پس چرا در chatbotهای قدیمی هم temperature داشتیم؟

چون آن chatbotها هم هنگام تولید متن معمولاً با یک توزیع احتمال سروکار داشتند. مدل در هر قدم نمی‌گفت «فقط یک جواب قطعی وجود دارد»؛ می‌گفت «این چند ادامه محتمل‌اند، با این احتمال‌ها». تنظیم temperature مشخص می‌کرد از این توزیع چقدر محافظه‌کارانه یا آزادانه نمونه‌گیری شود.

  • پاسخ فنی یا کدنویسی: معمولاً temperature پایین‌تر بهتر است، چون دنبال تنوع شاعرانه نیستیم؛ دنبال پاسخ پایدار و دقیق‌تریم.
  • ایده‌پردازی محصول، عنوان، متن تبلیغاتی: مقدار بالاتر می‌تواند مفید باشد، چون می‌خواهیم گزینه‌های متفاوت‌تری ببینیم.
  • خلاصه‌سازی سند: معمولاً مقدار پایین یا متوسط بهتر است، چون نباید چیز جدید و بی‌پشتوانه اضافه شود.

پس temperature یک تنظیم «شخصیت» یا «هوش» نیست؛ یک تنظیم روی مرحلهٔ انتخاب توکن است. مثل این است که از یک مسیر پیشنهادی، یا دقیقاً محتمل‌ترین قدم را برداریم، یا گاهی قدم‌های جایگزین اما هنوز محتمل را هم امتحان کنیم.

KV Cache

در generation لازم نیست Key و توکن‌های Value قبلی در هر step دوباره محاسبه شوند؛ KV cache آن‌ها را نگه می‌دارد. تأخیر کم می‌شود ولی memory با طول context رشد می‌کند.

چرا خروجی مدل یک‌باره تولید نمی‌شود؟

مدل‌های زبانی معمولاً توکن بعدی را تولید می‌کنند، بعد همان توکن را به متن قبلی اضافه می‌کنند و دوباره توکن بعدی را می‌سازند. یعنی هر خروجی بلند، حاصل یک حلقهٔ تکراری است. به همین دلیل انتخاب‌های اول روی ادامهٔ پاسخ اثر می‌گذارند.

  • Greedy: همیشه محتمل‌ترین توکن را انتخاب می‌کند. پاسخ قابل‌تکرارتر می‌شود، اما ممکن است خشک، تکراری یا گیرکرده باشد.
  • Top-p: از میان مجموعه‌ای از گزینه‌های محتمل نمونه‌گیری می‌کند. اگر مدل مطمئن باشد مجموعه کوچک می‌شود؛ اگر نامطمئن باشد گزینه‌های بیشتری وارد می‌شوند.
  • KV Cache: مثل نگه‌داشتن محاسبات قبلی است تا برای هر توکن جدید همهٔ گذشته از صفر محاسبه نشود.

هرچه خروجی طولانی‌تر شود، تصمیم‌های قبلی بیشتر روی مسیر بعدی اثر می‌گذارند؛ برای همین prompt خوب و محدودیت خروجی مهم است.

قطعی ≠ correct: temperature پایین ممکن است خروجی را تکرارپذیرتر کند، اما اگر محتمل‌ترین ادامه غلط باشد همان غلط را انتخاب می‌کند.

Hallucination، محدودیت و روش تطبیق

چرا پیش‌بینی توکن بعدی پایگاه حقیقت نیست؟

Hallucination یعنی خروجی روان و ظاهراً معتبر که با شواهد یا واقعیت پشتیبانی نمی‌شود. مدل برای تولید continuation محتمل آموزش دیده، نه برای query خودکار روی حقیقت بیرونی. عبارت hallucinated در این حوزه یعنی تولید بدون پشتوانه، نه تجربهٔ انسانی یا پزشکی.

سند مرتبط را هنگام request وارد context کن؛ مناسب دانش تازه، خصوصی و قابل‌استناد.

Fine-tuning، LoRA و QLoRA

در full fine-tuning همهٔ پارامتر‌ها update می‌شوند. LoRA وزن پایه را freeze می‌کند و update را با دو ماتریس کم‌رتبه یاد می‌گیرد: ΔW=BA. QLoRA مدل پایهٔ freezeشده را quantized نگه می‌دارد و گرادیان را به LoRA adapterها عبور می‌دهد تا memory کمتر شود. این روش‌ها برای behavior و domain مناسب‌اند، نه جایگزین database تازه.

Quantization

نمایش وزن‌ها با bit کمتر memory و bandwidth را کاهش می‌دهد، اما ممکن است approximation error وارد کند. storage dtype، compute dtype و dtype پارامترهای trainable جدا هستند؛ «مدل ۴ بیتی» به معنی ۴ بیتی‌بودن همهٔ عملیات نیست.

چه زمانی از کدام راه استفاده کنیم؟

خیلی از خطاها از اینجا می‌آیند که برای هر مشکل، یک راه‌حل محبوب را انتخاب کنیم. اما هر راه‌حل برای نوع خاصی از مشکل مناسب است. اگر مدل چیزی را نمی‌داند، همیشه جواب Fine-tuning نیست؛ اگر خروجی قالب بدی دارد، همیشه جواب RAG نیست.

  • دانش تازه یا قابل‌استناد: سند را بیاور، یعنی Retrieval / RAG. مدل با سند پاسخ می‌دهد و امکان ارجاع بهتر می‌شود.
  • رفتار تکرارشونده: اگر مدل باید سبک، قالب یا الگوی پاسخ مشخصی را بارها رعایت کند، Fine-tuning یا نمونه‌های خوب در prompt می‌تواند کمک کند.
  • محاسبه یا مشاهدهٔ بیرونی: اگر جواب باید از ماشین حساب، فایل، API یا دادهٔ زنده بیاید، استفاده از ابزار بهتر از حدس مدل است.

قاعدهٔ طلایی: هرجا پاسخ باید به واقعیت بیرونی وصل باشد، مدل را تنها نگذار؛ شواهد، ابزار یا ارزیابی کنار آن بگذار.

قاعدهٔ تصمیم: دانش متغیر → Retrieval؛ اقدام/مشاهدهٔ بیرونی → Tool؛ قالب معتبر → Schema؛ رفتار تکراری با example کافی → Fine-tuning؛ و در همهٔ حالت‌ها → ارزیابی.

خودآزمایی نهایی

۱. فرق logit و احتمال چیست؟

امتیاز Logit خام و نامحدود است. Softmax مجموعهٔ logitها را به احتمال‌های مثبت با مجموع ۱ تبدیل می‌کند.

۲. چرا Softmax داخل Attention استفاده می‌شود؟

امتیاز سازگاری Query/Key را به وزن‌های نسبی تبدیل می‌کند تا Valueها با یک توزیع وزن‌دار جمع شوند.

۳. Transformer بدون Attention چه اجزای مهم دیگری دارد؟

Embedding، positional information، FFN/MLP، residual، نرمال‌سازی، output projection و training objective.

۴. چرا RAG با Fine-tuning یکی نیست؟

شواهد RAG را هنگام request در context می‌آورد؛ پارامترهای Fine-tuning را برای behavior/task تغییر می‌دهد.

۵. آیا Attention weight توضیح قطعی reasoning مدل است؟

نه. می‌تواند سرنخ ارتباط باشد، اما به‌تنهایی تبیین علّی و کامل رفتار مدل نیست.
