۰

نقشهٔ راه: دقیقاً چه چیزی می‌سازیم؟

یک زنجیرهٔ علّی، نه فهرستی از اصطلاحات پراکنده.

داده→عدد و بردار→Neural Network→Probability→Token و Context→Attention→Transformer / LLM

مدل زبانی در بنیادی‌ترین سطح یک تابع بسیار بزرگ است: عدد می‌گیرد و عدد برمی‌گرداند. متن قبل از ورود به مدل به token id تبدیل می‌شود؛ هر id به embedding vector نگاشت می‌شود؛ لایه‌ها این بردارها را با توجه به context تغییر می‌دهند؛ در پایان برای token بعدی مجموعه‌ای logit ساخته و با Softmax به توزیع احتمال تبدیل می‌شود.

معیار یادگیری: در پایان باید بتوانی مسیر text → tokens → embeddings → Transformer blocks → logits → Softmax → next token را بدون نگاه‌کردن توضیح بدهی.

Machine Learning

به‌جای نوشتن همهٔ ruleها، parameterهای یک مدل از exampleها یاد گرفته می‌شوند.

Deep Learning

زیرمجموعه‌ای از ML که از Neural Networkهای چندلایه برای یادگیری representation استفاده می‌کند.

Large Language Model

یک Neural Network زبانی با parameter و دادهٔ زیاد؛ معمولاً مبتنی بر Transformer و هدف پیش‌بینی token.

آیا برای فهم این جزوه باید Calculus بلد باشم؟

نه. derivative و gradient را ابتدا به‌صورت «جهت و شدت تغییر» می‌فهمیم. فرمول‌ها برای اتصال intuition به کد هستند، نه آزمون ریاضی.

۱

عدد، بردار، ماتریس و Tensor

زبان مشترک تمام محاسبات مدل.

Scalar یک عدد است؛ مثلاً دما یا یک score. Vector لیستی مرتب از اعداد است؛ مثلاً نمایش یک token با ۷۶۸ ویژگی آموخته‌شده. Matrix جدولی دوبعدی از اعداد است. Tensor نام عمومی آرایه‌ای با هر تعداد بعد است.

Shape

scalar:  3.2               shape: []
vector:  [0.2, -1.1, 0.7] shape: [3]
matrix:  4 tokens × 8 dims shape: [4, 8]
batch:   32 × 4 × 8       shape: [32, 4, 8]

Weight و Bias

weight مشخص می‌کند هر ورودی چه اندازه و با چه علامتی اثر بگذارد. bias یک offset قابل‌یادگیری است تا مدل مجبور نباشد همه‌چیز را از صفر عبور دهد.

y = Wx + b

Dot Product: یک عدد برای میزان هم‌جهتی

دو بردار هم‌اندازه را عضو‌به‌عضو ضرب و جمع می‌کنیم. در Attention از این عملیات برای ساخت score شباهت Query و Key استفاده می‌شود.

[1, 2, 0] · [3, -1, 4] = (1×3) + (2×-1) + (0×4) = 1

Dot product بزرگ‌تر می‌تواند نشانهٔ هم‌جهتی بیشتر باشد، اما طول بردار هم روی آن اثر دارد. cosine similarity جهت را با نرمال‌کردن طول مقایسه می‌کند.

Dimension یعنی چه؟

وقتی می‌گوییم embedding دارای ۷۶۸ dimension است، منظور ۷۶۸ محور آموخته‌شده است. معمولاً نمی‌توان گفت محور ۴۲ دقیقاً «رسمی‌بودن» است؛ معنا میان تعداد زیادی dimension توزیع شده است.

چرا مدل فقط با عدد کار می‌کند؟

پردازنده عملیات جمع و ضرب را روی آرایه‌های عددی بسیار سریع اجرا می‌کند. آموزش هم به تابع‌های پیوسته و قابل‌مشتق نیاز دارد؛ string خام چنین ساختاری ندارد.

۲

از Linear Model تا Neuron

کوچک‌ترین واحد محاسباتی را بدون استعارهٔ زیستی بفهمیم.

یک artificial neuron چند ورودی را با weightهایشان ترکیب می‌کند، bias را اضافه می‌کند و معمولاً نتیجه را از یک activation function عبور می‌دهد:

z = w₁x₁ + w₂x₂ + … + wₙxₙ + b     ;     a = activation(z)

مثلاً برای تخمین احتمال incident، x₁ می‌تواند تعداد errorها و x₂ latency باشد. مدل هنگام training یاد می‌گیرد کدام feature مهم‌تر است. neuron یک مغز کوچک یا محل ذخیرهٔ یک مفهوم کامل نیست؛ فقط یک محاسبهٔ پارامتری است.

Parameter: مقداری که مدل از داده یاد می‌گیرد؛ مانند weight و bias. Hyperparameter: انتخابی بیرونی مانند learning rate، batch size یا تعداد لایه‌ها.

Forward Pass

حرکت از input به prediction را forward pass می‌نامیم. هنوز چیزی یاد گرفته نشده؛ فقط با parameterهای فعلی خروجی محاسبه شده است.

آیا هر neuron یک کلمه یا مفهوم مشخص را تشخیص می‌دهد؟

گاهی واحدهایی به pattern خاص حساس می‌شوند، اما representation معمولاً distributed است. نسبت‌دادن یک مفهوم انسانی ثابت به هر neuron مدل ذهنی قابل‌اعتمادی نیست.

۳

Neural Network و لایه‌ها

چرا یک خط کافی نیست و «عمیق» چه معنایی دارد؟

Input layer
x→Linear + Activation→Hidden representation→Output logits

ترکیب چند تابع خطی بدون activation هنوز یک تابع خطی است. Nonlinearity اجازه می‌دهد شبکه رابطه‌های پیچیده را مدل کند. Deep یعنی چندین مرحلهٔ representation پشت سر هم قرار گرفته‌اند.

Layer

یک تبدیل مشخص روی Tensor. در Transformer، Attention و Feed-Forward هر دو نوعی layer/sub-layer هستند.

Representation

شکل عددی‌ای که مدل در یک مرحله برای بیان اطلاعات ساخته است.

Parameter count

تعداد weightها و biasهای قابل‌یادگیری. «۷B» تقریباً یعنی هفت میلیارد parameter، نه هفت میلیارد خط کد.

Architecture

نقشهٔ اتصال لایه‌ها و جریان داده. Training parameterها را تعیین می‌کند؛ architecture ظرف محاسبات است.

Generalization و Overfitting

هدف حفظ‌کردن training set نیست؛ مدل باید روی example ندیده خوب کار کند. اگر training loss پایین ولی validation loss بالا باشد، احتمال overfitting وجود دارد. تقسیم train/validation/test کمک می‌کند یادگیری را از حفظ‌کردن جدا کنیم.

۴

Training: Loss، Gradient و Backpropagation

مدل دقیقاً چگونه weightهایش را تغییر می‌دهد؟

  1. Forward pass: مدل با weightهای فعلی prediction می‌سازد.
  2. Loss: یک عدد نشان می‌دهد prediction چقدر با target فاصله دارد.
  3. Backward pass: backpropagation سهم هر parameter در loss را با chain rule محاسبه می‌کند.
  4. Optimizer step: parameterها کمی در جهت کاهش loss تغییر می‌کنند.
  5. این چرخه روی batchهای فراوان تکرار می‌شود.
w_new = w_old − learning_rate × ∂Loss/∂w

gradient برداری از derivativeهاست: اگر هر parameter کمی تغییر کند، loss با چه جهت و شدتی تغییر می‌کند؟ gradient descent در خلاف جهت gradient حرکت می‌کند. learning rate اندازهٔ گام است؛ خیلی بزرگ می‌تواند training را ناپایدار و خیلی کوچک آن را کند کند.

Epoch

یک بار عبور تقریبی از کل training set.

Batch

گروهی از exampleها که یک‌جا پردازش و gradient آن‌ها تجمیع می‌شود.

Optimizer

قاعدهٔ به‌روزرسانی parameterها؛ مانند SGD یا Adam.

Vanishing و Exploding Gradient

در زنجیره‌های بسیار عمیق یا recurrent، ضرب derivativeها ممکن است gradient را نزدیک صفر یا بسیار بزرگ کند. ReLU، normalization، residual connection، initialization مناسب و gradient clipping از ابزارهای کنترل‌اند.

Backpropagation با Gradient Descent یکی است؟

نه. Backpropagation gradientها را به‌شکل کارآمد محاسبه می‌کند؛ Gradient Descent یا optimizer از آن‌ها برای update کردن parameterها استفاده می‌کند.

منبع nonlinearity و رفتارهای متفاوت خروجی.

تابعفرمول/بازهشهود و کاربرد

۶

Logit، Softmax و Cross-Entropy

پل میان score خام، احتمال و انتخاب token.

Logit چیست؟

خروجی خام مدل برای هر class یا token را logit می‌نامیم. logit احتمال نیست: می‌تواند منفی یا بزرگ‌تر از ۱ باشد و مجموعش محدودیتی ندارد.

softmax(zᵢ) = exp(zᵢ) / Σⱼ exp(zⱼ)

Softmax سه کار می‌کند: با exponential همهٔ مقدارها را مثبت می‌کند؛ score بزرگ‌تر را برجسته می‌کند؛ سپس با تقسیم بر مجموع، خروجی‌ها را به probabilityهایی تبدیل می‌کند که جمعشان ۱ است.

مثال دستی

برای logits برابر [2, 1, 0]، مقدارهای نمایی تقریباً [7.39, 2.72, 1] و مجموع 11.11 است؛ پس احتمال‌ها حدود [0.665, 0.245, 0.090] می‌شوند.

Numerical stability: در کد واقعی ابتدا بزرگ‌ترین logit را از همه کم می‌کنیم. Softmax تغییر نمی‌کند، ولی از overflow در exp جلوگیری می‌شود.

آزمایش تعاملی Softmax و Temperature

Temperature قبل از Softmax logits را تقسیم می‌کند. T < 1 distribution را متمرکزتر و T > 1 آن را تخت‌تر می‌کند. Temperature دانش مدل را عوض نمی‌کند، فقط sampling از scoreهای فعلی را تغییر می‌دهد.

Cross-Entropy چه می‌سنجد؟

اگر target صحیح class شمارهٔ ۲ باشد، loss ساده برابر -log(p₂) است. احتمال زیاد برای جواب درست loss کوچک و احتمال کم loss بزرگ می‌دهد.

CrossEntropy(target=k) = −log(softmax(logits)ₖ)
آیا خروجی Softmax «اعتماد واقعی» مدل است؟

نه لزوماً. Probability مدل ممکن است calibration خوبی نداشته باشد. ۹۰٪ در distribution خروجی تضمین نمی‌کند پاسخ در جهان واقعی ۹۰٪ درست است.

۷

Token، Vocabulary، One-Hot و Embedding

چگونه متن به ورودی عددی معنادار تبدیل می‌شود؟

Tokenizer متن را به واحدهایی به نام token تقسیم می‌کند. token ممکن است یک کلمه، بخشی از کلمه، علامت یا byte باشد. سپس هر token از vocabulary یک id می‌گیرد. id فقط شناسه است و نزدیکی عددی idها معنایی ندارد.

text:      "مدل‌ها یاد می‌گیرند"
tokens:    ["مدل", "‌ها", " یاد", " می", "‌گیرند"]
token_ids: [8142, 391, 2207, 118, 9201]   # illustrative only

One-Hot چرا کافی نیست؟

در بردار one-hot فقط خانهٔ مربوط به id برابر ۱ است. دو کلمهٔ مشابه و نامشابه فاصله‌ای یکسان دارند و vector بسیار بزرگ و sparse است. embedding table برای هر token یک بردار dense و قابل‌یادگیری نگه می‌دارد.

embedding(token_id) = row[token_id] from E ∈ ℝ^(vocab_size × d_model)

Word2Vec چه ایده‌ای اضافه کرد؟

Word2Vec embedding را از یک task جانبی یاد می‌گیرد: در Skip-gram از کلمهٔ مرکزی همسایه‌ها پیش‌بینی می‌شوند و در CBOW از همسایه‌ها کلمهٔ مرکزی. واژه‌هایی با context مشابه بردارهای نزدیک‌تری پیدا می‌کنند. محدودیت: یک واژه معمولاً یک بردار static دارد و چندمعنایی را با context حل نمی‌کند.

Subword Tokenization

تقسیم به subword میان vocabulary کاملاً کلمه‌ای و character-level تعادل ایجاد می‌کند: واژهٔ نادر می‌تواند از بخش‌های آشناتر ساخته شود. BPE یکی از روش‌های تاریخی مهم این مسیر است. مرز token همیشه با مرز واژه یا معنا یکی نیست.

Token ≠ word: هزینه، context length و احتمال خروجی بر حسب token محاسبه می‌شوند. یک واژهٔ فارسی ممکن است چند token شود.
۸

Sequence، RNN و گلوگاه Context

چرا قبل از Transformer پردازش ترتیبی مسئله‌ساز بود؟

معنای زبان به ترتیب و context وابسته است. RNN در هر time step ورودی فعلی و hidden state قبلی را ترکیب می‌کند:

hₜ = f(xₜ, hₜ₋₁)

این state خلاصه‌ای از گذشته است. LSTM و GRU با gateها جریان حافظه و gradient را بهتر کردند، اما سه محدودیت اصلی باقی ماند:

Sequential compute

برای محاسبهٔ h₁₀ ابتدا h₉ لازم است؛ parallelization دشوار می‌شود.

Long dependency

رابطهٔ دو token دور باید از stateهای میانی زیادی عبور کند.

Fixed bottleneck

Encoder کلاسیک کل ورودی را به یک vector ثابت برای Decoder تحویل می‌داد.

Attention ابتدا برای رفع گلوگاه آخر در Neural Machine Translation مطرح شد: Decoder به‌جای تکیه بر یک خلاصهٔ ثابت، در هر گام به همهٔ stateهای Encoder نگاه می‌کند.

۹

Attention: جست‌وجوی نرم در حافظه

Q، K، V و Softmax را از یک مثال ملموس بسازیم.

Query بیان می‌کند «چه می‌خواهم؟»، هر Key می‌گوید «این رکورد با چه ویژگی‌ای قابل‌جست‌وجوست؟» و Value محتوایی است که در صورت مرتبط‌بودن برداشته می‌شود. برخلاف database lookup سخت، Attention معمولاً همهٔ Valueها را با وزن متفاوت ترکیب می‌کند.

Query (Q)

نیاز representation فعلی؛ دنبال چه رابطه‌ای هستم؟

Key (K)

نمایهٔ قابل‌مقایسهٔ هر موقعیت برای محاسبهٔ relevance.

Value (V)

اطلاعاتی که پس از تعیین weight واقعاً تجمیع می‌شود.

  1. از representation ورودی با matrixهای آموختنی، Q و K و V بساز.
  2. برای هر Query، با dot product همهٔ Keyها score بساز.
  3. score را بر √dₖ تقسیم کن تا دامنه کنترل شود.
  4. با Softmax scoreها را به attention weight تبدیل کن.
  5. جمع وزن‌دار Valueها را خروجی بگیر.
Attention(Q,K,V) = softmax(QKᵀ / √dₖ) V

اگر scoreهای یک Query برای سه token برابر [2, 1, 0] باشند، Softmax تقریباً weightهای [0.665, 0.245, 0.090] می‌سازد. خروجی 0.665V₁ + 0.245V₂ + 0.090V₃ است؛ مدل فقط یک token را انتخاب نکرده است.

چرا scaling؟

با بزرگ‌شدن dimension، dot productها می‌توانند magnitude بزرگی پیدا کنند. Softmax روی اختلاف‌های بزرگ اشباع و gradient کوچک می‌شود. تقسیم بر ریشهٔ dimension کلید، variance scoreها را کنترل می‌کند.

Q/K/V خود token نیستند: projectionهای متفاوتی از representation هستند: Q=XWQ, K=XWK, V=XWV.
نوعمنبع Qمنبع K/Vمحدودیت دید
Self-Attentionهمان sequenceهمان sequenceموقعیت‌های مجاز همان ورودی
Cross-AttentionDecoder/مقصدEncoder/منبعحافظهٔ منبع
Causal Self-Attentionهمان sequenceهمان sequenceفقط گذشته و موقعیت جاری
۱۰

ترجمهٔ مفهومی «Attention Is All You Need»

مقالهٔ Vaswani و همکاران، ۲۰۱۷؛ شرح محتوایی به‌جای ترجمهٔ کلمه‌به‌کلمه.

ایدهٔ مرکزی مقاله: برای sequence transduction لازم نیست recurrence یا convolution هستهٔ ارتباط میان tokenها باشد. می‌توان معماری Encoder–Decoder را بر Attention بنا کرد، موقعیت‌های هر layer را موازی‌تر محاسبه کرد و مسیر ارتباط tokenهای دور را کوتاه کرد.

مسئله‌ای که مقاله از آن شروع می‌کند

مدل‌های ترجمهٔ قوی آن زمان عمدتاً RNN/CNN بودند. RNN محاسبه را ترتیبی می‌کرد و dependency دور مسیر بلندی داشت. Attention پیش‌تر در کنار RNN موفق شده بود، اما این مقاله پرسید: اگر Attention را از جزء کمکی به سازوکار اصلی تبدیل کنیم چه می‌شود؟ پاسخ معماری Transformer بود.

Abstract به زبان ساده

نویسندگان یک Encoder–Decoder بدون recurrence و convolution پیشنهاد کردند که برای ارتباط میان موقعیت‌ها از Attention استفاده می‌کند. در آزمایش‌های ترجمهٔ انگلیسی–آلمانی و انگلیسی–فرانسوی، مدل آن‌ها کیفیت قوی و training موازی‌پذیرتری ارائه کرد. مقاله همچنین تعمیم معماری را روی parsing بررسی کرد.

Encoder چه می‌کند؟

هر Encoder layer در مقاله دو sub-layer دارد: Multi-Head Self-Attention و یک position-wise Feed-Forward Network. دور هر sub-layer یک residual connection و سپس Layer Normalization قرار می‌گیرد. هر token از tokenهای دیگر همان ورودی information می‌گیرد.

Decoder چه می‌کند؟

Decoder سه sub-layer دارد: masked Self-Attention روی tokenهای خروجی قبلی، Cross-Attention که Query را از Decoder و Key/Value را از Encoder می‌گیرد، و Feed-Forward. Mask اجازه نمی‌دهد موقعیت خروجی پاسخ آینده را ببیند.

Scaled Dot-Product Attention

مقاله Queryها را با Keyها ضرب می‌کند، scale را اعمال می‌کند، mask احتمالی را پیش از Softmax وارد می‌کند و weightهای حاصل را روی Valueها می‌زند. matrix ارتباط همهٔ Queryها با همهٔ Keyها هم‌زمان ساخته می‌شود.

Multi-Head یعنی چه؟

به‌جای یک Attention، Q/K/V به چند فضای کوچک‌تر project می‌شوند. هر head Attention مستقل خود را محاسبه می‌کند؛ خروجی headها concatenate و با projection نهایی مخلوط می‌شود. مدل می‌تواند چند نوع رابطه را در subspaceهای مختلف دنبال کند، اما هر head الزاماً یک مفهوم انسانی ثابت ندارد.

headᵢ = Attention(QWᵢQ, KWᵢK, VWᵢV)
MultiHead = Concat(head₁,…,headₕ)Wᴼ

Position چرا لازم است؟

Self-Attention خام ترتیب را از index نمی‌فهمد. مقاله sinusoidal positional encoding را به embedding ورودی اضافه کرد. Transformerهای بعدی روش‌های دیگری مانند learned position یا rotary position به‌کار بردند؛ اصل نیاز به position پابرجاست.

Feed-Forward، Residual و Normalization

Attention میان tokenها اطلاعات جابه‌جا می‌کند. FFN روی هر position یک تبدیل nonlinear انجام می‌دهد. Residual مسیر مستقیم عبور اطلاعات می‌سازد و normalization training را پایدارتر می‌کند. پس عنوان مقاله به معنی حذف همهٔ اجزای غیر Attention نیست.

Embedding تا Vocabulary

در انتهای Decoder، linear projection برای هر token واژگان logit می‌سازد و Softmax distribution خروجی را تولید می‌کند. هنگام training، sequence هدف یک موقعیت shift می‌شود: prefix ورودی است و token بعدی label.

چرا path length مهم بود؟

در RNN انتقال اطلاعات از ابتدای sequence به انتها چندین step داشت. در Self-Attention، هر موقعیت در یک layer مستقیماً با هر موقعیت مجاز score دارد. هزینهٔ مهم آن، matrix توجه با رشد تقریباً quadratic نسبت به sequence length است.

مقاله چه چیزی نمی‌گوید؟

  • مقاله دربارهٔ chatbot، instruction following، RLHF، agent یا tool use نیست.
  • ثابت نمی‌کند recurrence برای همهٔ مسئله‌ها بی‌ارزش شده است.
  • نمی‌گوید Attention توضیح‌پذیری کامل فراهم می‌کند.
  • Transformerهای امروز جزئیات اجرایی متفاوتی با نسخهٔ original دارند.
خلاصهٔ یک‌دقیقه‌ای: مقاله گلوگاه پردازش ترتیبی را هدف گرفت؛ با Self-Attention ارتباط مستقیم میان tokenها ساخت؛ Multi-Head چند projection موازی داد؛ position ترتیب را وارد کرد؛ Encoder/Decoder با FFN، residual و normalization کامل شدند؛ linear + Softmax token خروجی را پیش‌بینی کرد.
چرا عنوان «Attention Is All You Need» کمی اغراق‌آمیز است؟

چون مدل علاوه بر Attention به embedding، positional encoding، FFN، residual، normalization، objective، optimizer و داده نیاز دارد. عنوان به حذف recurrence/convolution از هستهٔ sequence modeling اشاره می‌کند.

Causal Mask

در position شمارهٔ t، scoreهای آینده با مقدار بسیار منفی mask می‌شوند تا پس از Softmax weight تقریباً صفر بگیرند. بدون mask، مدل هنگام training پاسخ آینده را می‌بیند.

Multi-Head و Shape

اگر d_model=512 و h=8 باشد، معمولاً هر head بعد ۶۴ دارد. Q/K/V برای همهٔ tokenها ساخته و به headها reshape می‌شوند. خروجی headها دوباره به dimension اصلی برمی‌گردد.

Residual Stream

می‌توان representation هر token را یک stream در نظر گرفت. Attention و MLP تغییراتی به آن اضافه می‌کنند. Residual باعث می‌شود هر sub-layer لازم نباشد representation را از صفر بازسازی کند.

از Transformer تا LLM

Pre-training، objective و رفتاری که از scale پدیدار می‌شود.

Pre-training

در decoder-only language model، متن به exampleهای فراوان next-token prediction تبدیل می‌شود. label از خود متن می‌آید، بنابراین روش self-supervised است. مدل برای کاهش Cross-Entropy مجبور می‌شود الگوهای syntax، semantics، سبک و facts موجود در داده را در parameterهایش فشرده کند.

P(x₁,…,xₙ) = ∏ₜ P(xₜ | x₁,…,xₜ₋₁)

BERT چه تفاوتی دارد؟

BERT اصلی Encoder-only و bidirectional است. بخشی از tokenها در Masked Language Modeling پنهان/خراب می‌شوند و مدل با context چپ و راست آن‌ها را بازسازی می‌کند. interface پیش‌فرضش تولید autoregressive آزاد نیست.

Pre-training

یادگیری عمومی از corpus بزرگ؛ بسیار پرهزینه و طولانی.

Fine-tuning / Alignment

تطبیق behavior یا task با dataset کوچک‌تر.

Inference

Context Window و Parameter Memory

Context window فضای موقت tokenهای همین request است. parameterها الگوهای فشردهٔ training هستند. افزودن سند به prompt با تغییر weightها یکی نیست؛ Retrieval اطلاعات را موقتاً در context می‌آورد، Fine-tuning behavior را در parameterها تغییر می‌دهد.

Inference و Decoding

چگونه distribution به متن خروجی تبدیل می‌شود؟

  1. Prompt tokenize و forward pass اجرا می‌شود (prefill).
  2. از logits آخرین position یک token انتخاب می‌شود.
  3. token انتخابی به context افزوده و گام بعد اجرا می‌شود (decode).
  4. این حلقه تا stop token یا محدودیت خروجی ادامه می‌یابد.
روشرفتارنکته

KV Cache

در generation لازم نیست Key و Value tokenهای قبلی در هر step دوباره محاسبه شوند؛ KV cache آن‌ها را نگه می‌دارد. latency کم می‌شود ولی memory با طول context رشد می‌کند.

Deterministic ≠ correct: temperature پایین ممکن است خروجی را تکرارپذیرتر کند، اما اگر محتمل‌ترین ادامه غلط باشد همان غلط را انتخاب می‌کند.
۱۴

Hallucination، محدودیت و روش تطبیق

چرا next-token prediction پایگاه حقیقت نیست؟

Hallucination یعنی خروجی روان و ظاهراً معتبر که با evidence یا واقعیت پشتیبانی نمی‌شود. مدل برای تولید continuation محتمل آموزش دیده، نه برای query خودکار روی حقیقت بیرونی. عبارت hallucinated در این حوزه یعنی تولید بدون پشتوانه، نه تجربهٔ انسانی یا پزشکی.

Retrieval / RAG

سند مرتبط را هنگام request وارد context کن؛ مناسب دانش تازه، خصوصی و قابل‌استناد.

Tool use

برای log، database، calculator یا API به‌جای حدس، observation واقعی بگیر.

Structured output

schema شکل خروجی را کنترل می‌کند؛ صحت factual را به‌تنهایی تضمین نمی‌کند.

Evaluation

روی dataset دیده‌نشده، metric و baseline تعریف کن.

Fine-tuning، LoRA و QLoRA

در full fine-tuning همهٔ parameterها update می‌شوند. LoRA weight پایه را freeze می‌کند و update را با دو matrix کم‌رتبه یاد می‌گیرد: ΔW=BA. QLoRA مدل پایهٔ freezeشده را quantized نگه می‌دارد و gradient را به LoRA adapterها عبور می‌دهد تا memory کمتر شود. این روش‌ها برای behavior و domain مناسب‌اند، نه جایگزین database تازه.

W′ = W + BA    where rank r ≪ model dimension

Quantization

نمایش weightها با bit کمتر memory و bandwidth را کاهش می‌دهد، اما ممکن است approximation error وارد کند. storage dtype، compute dtype و dtype پارامترهای trainable جدا هستند؛ «مدل ۴ بیتی» به معنی ۴ بیتی‌بودن همهٔ عملیات نیست.

قاعدهٔ تصمیم: دانش متغیر → Retrieval؛ اقدام/مشاهدهٔ بیرونی → Tool؛ قالب معتبر → Schema؛ رفتار تکراری با example کافی → Fine-tuning؛ و در همهٔ حالت‌ها → Evaluation.

خودآزمایی نهایی

۱. فرق logit و probability چیست؟

Logit score خام و نامحدود است. Softmax مجموعهٔ logitها را به probabilityهای مثبت با مجموع ۱ تبدیل می‌کند.

۲. چرا Softmax داخل Attention استفاده می‌شود؟

score سازگاری Query/Key را به weightهای نسبی تبدیل می‌کند تا Valueها با یک distribution وزن‌دار جمع شوند.

۳. Transformer بدون Attention چه اجزای مهم دیگری دارد؟

Embedding، positional information، FFN/MLP، residual، normalization، output projection و training objective.

۴. چرا RAG با Fine-tuning یکی نیست؟

RAG evidence را هنگام request در context می‌آورد؛ Fine-tuning parameterها را برای behavior/task تغییر می‌دهد.

۵. آیا Attention weight توضیح قطعی reasoning مدل است؟

نه. می‌تواند سرنخ ارتباط باشد، اما به‌تنهایی تبیین علّی و کامل رفتار مدل نیست.
